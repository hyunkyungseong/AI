> 상태: ✅ 배포 완료(2026-08-30) — 사용자 브라우저 확인 완료. 코드 파일(`scripts/api.py`·`scripts/billing.py`) +

> 이번 배포는 **코드 파일 2개만 복사하면 끝**입니다. DB 구조 변경(마이그레이션)이 없습니다.

## 오늘 작업 요약
1. **"요청내용"(거래명세서 엑셀 첫 번째 표지 시트) 실데이터 채우기** (`.claude/plans/plan_요청내용표지채우기.md`) — 지금까지 항상 빈칸이던 표지 시트에 사업자등록증·법인명·발행일자·품목·공급가액·세액·합계·담당자이메일·비고·거래명세서번호를 실제 값으로 채움. 조가 여러 개라 시트가 여러 장으로 합쳐지는 경우에도 표지가 항상 맨 앞에 포함됨.
2. **표지 "담당자이메일" 필드 수정** — 처음엔 내부 계정 담당자 이메일을 넣었는데, 거래처마스터에 등록된 거래처 **수신이메일**을 넣도록 수정.

(같은 세션에서 고친 "거래명세서 미리보기 경고 배너 많을 때 버튼 접근 불가" 버그는 **프론트엔드 전용**이라 이 배포에 포함되지 않습니다 — 로컬 PC Next.js가 이미 반영된 상태입니다.)

## 1단계 — 코드 파일 복사
로컬 PC의 아래 2개 파일을 사무실 PC의 같은 경로(`scripts/`)로 덮어씁니다.

- `scripts/api.py`
- `scripts/billing.py`

**`init_db_mariadb.py` 실행(마이그레이션)은 필요 없습니다** — 기존 컬럼(거래처마스터.사업자등록번호·수신이메일, 거래명세서.품목/공급가액/세액/합계)만 읽어서 씁니다. **프론트엔드 파일도 복사할 필요 없습니다** — 화면은 로컬 PC의 Next.js가 그대로 담당하고, `frontend/.env.local`의 `FASTAPI_URL`로 사무실 PC를 가리켜 씁니다.

## 2단계 — API 서버 재시작
1. 기존에 떠 있는 API 서버 창을 닫거나 Ctrl+C로 종료(포트 8001)
2. `API서버_실행_사무실PC.bat` 다시 실행
3. 브라우저에서 `http://localhost:8001/health` 접속 → 정상 응답 확인

여기까지 하면 배포 끝입니다.

## 배포 후 확인할 것 (브라우저)
1. 조가 1개뿐인 거래처(예: 삼성화재해상보험(주))의 발행완료 거래명세서를 다운로드 → 엑셀 첫 번째 시트("요청내용")에 사업자등록증·법인명·발행일자·품목·공급가액·세액·합계·거래명세서번호가 실제 값으로 채워져 있는지 확인
2. 같은 파일의 "담당자이메일" 칸이 거래처마스터에 등록된 **수신이메일**(예: 삼성화재해상보험(주) → jooyeon1178.kang@samsung.com)로 나오는지 확인 — 거래명세서 본문 시트 하단의 담당자 연락처(내부 담당자)는 예전처럼 그대로 나와야 함
3. 조가 여러 개인 거래처의 거래명세서를 다운로드 → 여전히 첫 번째 시트가 "요청내용" 표지로 나오고, "비고" 칸에 "시트참조(...)"가 표시되는지 확인
4. 위 파일들 모두 Excel에서 열었을 때 "복구" 관련 경고 없이 정상적으로 열리는지 확인
