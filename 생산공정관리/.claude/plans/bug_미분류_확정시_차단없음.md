## 요약

거래명세서 미리보기에서 왼쪽 "원본(자동계산)" 항목 중 어느 조건식에도 안 걸린("미분류") 항목이
남아있어도, "확정" 버튼이 막히거나 경고 팝업이 뜨지 않고 그대로 발행요청목록으로 넘어간다 —
그 미분류 항목의 금액이 통째로 청구서에서 누락된다.

## 실사례 (D-202608-00079, 현대해상)

- 오늘 배포한 출력비 자재별 비례배분 기능으로 원본 "출력비(다이렉트)"가 자재 그룹 2개("XP" 16원·
  "FXP" 20원)로 갈라짐
- 같이 저장한 조건식(청구품목규칙 id=256, "양면출력(FXP)")이 `자재명 == "FXP"`만 매칭하도록 등록돼
  "XP" 그룹(6,060개, 96,960원)이 미분류로 남음
- 확정 버튼 클릭 시 아무 경고 없이 통과 → 실제 저장된 합계가 원본(1,000,189원)보다 96,960원(+세액)
  적은 903,229원으로 발행요청목록에 등록됨

## 원인

- 왼쪽 원본 표의 체크(✓) 표시(2026-07-24)와 "총 N건 | 선택 N건 | 미선택 N건" 요약(2026-08-09)은
  구현돼 있어 사용자가 "눈으로 보면" 알 수 있지만, **"미선택(미분류) 건수가 있으면 확정을 막는다"는
  로직 자체가 처음부터 구현된 적이 없음** — `docs/CHANGELOG.md` 전체와
  `frontend/components/InvoicePreviewDialog.tsx`의 확정 버튼 `disabled` 조건(`submitting`·
  `rightRows.length===0`·`부가세오류`·`통합조건식_불일치`)·`handleConfirmClick()` 함수를 직접
  확인해 재검증함(2026-08-17)
- 지금까지는 출력비·봉입비가 항상 한 줄이라 조건식이 놓치는 경우가 실질적으로 드물어서 이 gap이
  드러나지 않았음 — 오늘 자재별 분할 기능으로 미분류가 실제로 생기는 사례가 처음 나오면서 실제
  금액 누락으로 이어짐

## 다음에 착수할 때 검토할 것

1. **확정 버튼 비활성화**: 미분류 건수 > 0이면 "확정" 버튼 자체를 disabled 처리
   - 장점: 실수 자체를 원천 차단
   - 단점: "의도적으로 일부 항목을 미분류로 남기고 확정하고 싶은" 정상 케이스가 있는지 먼저 확인
     필요(예: 금액 0원짜리 미분류는 무해할 수 있음 — `billing.적용_규칙()`이 이미 수량/금액 0인
     규칙적용결과는 걸러내는 것과 같은 기준 적용 검토)
2. **확정 시 경고 팝업**(`window.confirm()` 또는 커스텀 확인창): 미분류 금액 합계를 보여주고
   "그래도 확정하시겠습니까?" — 기존 `통합조건식_불일치` 배너·"겹치는 항목" 확인창(2026-08-09)과
   유사한 패턴 재사용 가능
3. 어느 방향이든 `InvoicePreviewDialog.tsx`의 `매칭Set`/`미분류` 계산 로직(이미 있음, 라인
   ~299~328)을 그대로 재사용하면 됨 — 새로 계산할 것 없음
4. 사용자가 원하는 정확한 UX(1번/2번 중 어느 쪽, 또는 혼합)를 먼저 확인 후 착수
