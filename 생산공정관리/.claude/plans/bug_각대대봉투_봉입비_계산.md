# 버그 수정: "봉입비"에서 각대대봉투 가산 제거 (수작업건수 데이터 없음) — ✅ 코드 수정·검증·사무실 PC 배포 전부 완료 (2026-07-22)

## Context (왜 필요한가)

사용자가 의뢰서 95073(미래에셋증권)에서 미발행목록 "봉입건수"(6,090)와 거래명세서 미리보기 "봉입비" 수량(7,670)이 다르게 표시되는 걸 발견해 원인 분석 요청 → 1차로 "각대대봉투 단가 미등록 시 계산 방식" 버그를 발견·수정(`_혼합단가_행목록()`, `bug_각대대봉투_단가규칙.md` 아님 — 같은 대화 세션에서 이어진 2차 수정이라 이 파일 하나로 정리) → 사용자가 실제 자료(각대봉투 1,580 + 창봉투 4,510 = 6,090 = 봉입건수와 정확히 일치)를 다시 확인해보니 **"봉입비"(공임) 계산식 자체가 애초에 잘못 설계**돼 있었다는 게 추가로 드러남.

**올바른 개념(사용자 확정, 2026-07-22):**
- "봉입비" = **봉입건수(기계작업) × 봉입단가** + **수작업건수 × 각대대봉투봉입단가("수작업 단가")**
- 각대대봉투는 기계가 아니라 사람이 손으로 처리해야 해서 별도 수작업 비용이 발생하는데, 이 "수작업건수"는 **개별 작업 건별 봉투형태 데이터가 있어야 계산 가능**하고, **지금은 그 데이터를 받아오지 못해 계산 자체가 불가능**함
- 지금까지 코드는 "수작업건수"를 "각대대봉투 자재 사용량"으로 대충 대체해서 봉입비에 더하고 있었음(예: 95073은 6,090+1,580=7,670) — 이게 잘못된 근사치였음
- **지금 할 일**: 수작업건수를 반영할 수 없는 현재 상태에서는 봉입비 = 봉입건수 × 봉입단가만 청구(각대대봉투 가산 없음, 즉 사실상 수작업비=0으로 둠)
- **나중에**(개별 작업 건의 봉투형태 데이터를 받을 수 있게 되면) 봉입건수(기계작업)와 수작업건수를 분리해서 각각 표기 — 이건 이번 범위 아님, 데이터가 들어오기 시작하면 별도 작업(아래 "향후 작업" 참고)

**"봉입자재비"(E, 봉투제작비)는 그대로 유지** — 이건 실물 봉투 자재 값(창봉투/각대봉투 각각의 원가)이라 1차 수정에서 고친 "각대대봉투단가 등록 여부에 따라 분리/합산/무상" 로직이 여전히 맞음. 이번엔 "봉입비"(공임)에서만 각대대봉투 가산을 빼면 됨.

## 1차 수정 내용 (완료, 참고용)

`scripts/billing.py`에 공용 헬퍼 `_혼합단가_행목록(일반수량, 대대수량, 일반단가, 대대단가)` 신규 — "일반+각대대봉투 두 수량이 있고 하나는 단가가 등록 안 될 수 있는 품목"의 (수량,단가) 조합을 사용자 확정 규칙대로 만듦(둘 다 등록→분리, 하나만 등록→그 단가로 합산, 둘 다 없음→무상). `calc_공급가맵()`·`build_품목행()`의 "봉입비"·"봉입자재비/봉투제작비" 계산에 적용했었음 — **이번 2차 수정에서 "봉입비"는 이 헬퍼 적용을 다시 빼고 단순 계산으로 되돌림** (아래 참고), "봉입자재비/봉투제작비"는 그대로 유지.

## 2차 수정 설계 (이번 작업)

### `scripts/billing.py`

**`build_품목행()`**:
- "봉입비"를 혼합항목에서 빼서 단순 항목(`항목계산`)으로 되돌림 — `(봉입건수, rates.get("봉입단가", 0))` 그대로, 각대대봉투 관련 없음
- "봉입자재비"는 혼합항목(`_혼합단가_행목록` 사용)에 그대로 유지

**`calc_공급가맵()`**:
- "봉입비" 항목금액을 `봉입건수 * rates.get("봉입단가", 0)` 단순 계산으로 되돌림(`_혼합단가_행목록` 미사용)
- "봉투제작비"는 `_혼합단가_행목록` 기반 계산 그대로 유지
- 항목수량["봉입비"]도 `봉입건수`만으로 되돌림(아무 데도 안 쓰이는 값이지만 일관성을 위해 함께 고침)

`_혼합단가_행목록()` 헬퍼 자체는 그대로 유지(봉입자재비/봉투제작비에서 계속 사용).

## 검증 방법
1. `python -m py_compile scripts/billing.py`
2. 95073 데이터로 재구성 검증: "봉입비" 수량이 이제 6,090(봉입건수만) · 금액 = 6,090×14 = 85,260원이 되는지 확인, "봉입자재비"는 1차 수정 그대로(6,090, 22원, 133,980원) 유지되는지 확인
3. `calc_공급가맵()`·`build_품목행()` 두 함수의 합계가 여전히 서로 일치하는지 확인
4. 회귀 확인 — 각대대봉투 미사용 실제 발행 건(D-202607-00009)은 이번 수정으로도 전혀 영향 없어야 함
5. 1차 수정 때 만든 "각대대단가 등록 시 분리 계산" 가상 테스트 케이스도 다시 돌려서 봉입자재비 쪽은 여전히 정상 분리되는지, 봉입비 쪽은 이제 각대대봉투와 무관하게 항상 봉입건수만 쓰는지 함께 확인

## 비개발자용 확인 체크리스트
