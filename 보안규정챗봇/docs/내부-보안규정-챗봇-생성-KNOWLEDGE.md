## 🏗️ 핵심 아키텍처 결정사항

### 1. 응답 방식 — LLM 제거, 조항 직접 표시
- AI 합성 답변(느림) → **원문 조항 직접 표시(빠름)**
- 이유: 규정 문서는 원문이 가장 정확하고 신뢰도 높음
- Ollama/LLM 불필요 → 응답 속도 1~2초

### 2. 문서 파싱 — 장(章)/조(條) 구조 단위 (ingest.py)
- **제N조 단위로 파싱** → 조항 전체가 하나의 검색 단위
- 목차·개정이력 자동 제거: 마지막 `제1장` 위치부터 파싱 시작
- **머리글·꼬리글 자동 제거**: 전체 페이지의 30%↑ 반복 줄 + 페이지 번호 패턴 제거
- **행정 조항 자동 제외**: 목적·적용범위·용어정의·수립·공표·경과조치·예외적용 조항은 벡터 저장소에 미포함
  - 이유: FAISS가 이런 조항을 어떤 질문에도 광범위하게 매칭하는 오류 방지

### 3. 검색 방식 — RRF 기반 하이브리드 검색 (app.py)
- **FAISS** (의미 검색) + **BM25** (키워드 검색) → RRF 점수 합산
- **RRF (Reciprocal Rank Fusion)**: 두 검색 결과의 순위를 합산, 양쪽에서 모두 높은 문서가 최상위
- **FAISS 단독 결과 필터**: BM25 점수 0이면서 FAISS 거리 > 0.8이면 제외 (관련 없는 조항 차단)
- **코퍼스 불용어 자동 계산**: 앱 시작 시 전체 조항의 70%↑ 등장 단어를 BM25 쿼리에서 자동 제외
- **키워드 분리**: 문서 색인용(명사+동사) vs 쿼리용(명사 전용) 토크나이저 분리 → 질문 동사 오매칭 방지

### 4. 쿼리 확장 — 보안 동의어 테이블 (app.py)
- 사용자 일상어와 문서 법규 용어 간 간격을 수동 테이블로 연결
- 향후 사전 학습 FastText(저장 공간 확보 후)로 대체 예정

```python
SECURITY_SYNONYMS = {
    "암호":     ["비밀번호", "패스워드"],
    "비밀번호": ["암호", "패스워드"],
    "접근통제": ["접근제어", "권한관리", "접근권한"],
    "파기":     ["삭제", "폐기", "말소"],
    "침해":     ["해킹", "유출", "사고"],
    "유출":     ["침해", "노출", "누출"],
    "계정":     ["사용자", "권한"],
    "접근권한": ["계정", "권한"],
    # 필요 시 이 테이블에 한 줄 추가
}
```

### 5. UI — 아코디언 방식
- 조항 타이틀(장+조 표시)만 먼저 노출
- 클릭 시 조항 내용 펼침
- 장 정보는 타이틀 위에 작게 표시

## 📖 주요 파라미터
| 항목 | 값 | 설명 |
|---|---|---|
| SCORE_THRESHOLD | 1.2 | FAISS L2 거리 임계값 |
| STRICT_FAISS_THRESHOLD | 0.8 | BM25 미지원 시 FAISS 단독 허용 임계값 |
| RRF_K | 60 | RRF 계산 상수 (표준값) |
| CORPUS_STOPWORDS 기준 | 70% | 전체 조항의 70% 이상 등장 단어 = 불용어 |
| 최소 한글 문자 | 50자 | 조항 본문 최소 길이 (목차 필터링) |
| 검색 결과 최대 | 5개 | RRF 점수 상위 5개 |

```

├── data/               ← 보안규정 문서 (PDF, docx)

├── logs/               ← 질문 이력 (questions.jsonl)
├── templates/
│   └── index.html      ← 챗봇 UI (아코디언)
├── app.py              ← Flask 웹 서버
├── ingest.py           ← 문서 처리 (장/조 파싱 → 벡터 저장소 생성)
├── requirements.txt
└── docs/               ← 이 파일 포함
```
