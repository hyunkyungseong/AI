# 버그 수정: 추가봉입비가 봉투 삽입이 없는 작업(반제품·제본단독)에도 장수 전체로 과다청구되던 문제 — ✅ 완료(로컬 코드 2026-08-22, 사무실 PC 배포 2026-08-23)

## Context (왜 필요한가)

실사용 검수 중(삼성화재해상보험(주) · 계약보전(PLK)웰컴팩, 의뢰서 96315) 미리보기 화면에서 반제품
작업("계약보전_맞춤형약관")의 "추가봉입비"가 62,944 × 25원 = 1,573,600원으로 잡히는 걸 발견 →
조사 결과 `scripts/billing.py`의 `_작업별_품목누적()`이 이 기능(`.claude/plans/plan_공정별단가청구.md`)
착수 훨씬 전인 **2026-07-19 billing.py 최초 작성 시점부터** 갖고 있던 계산식 결함으로 확인됨.

## 원인

```python
추가용지 = max(0, 장수 - 봉입건수)   # 수정 전
```

"추가봉입비"는 봉투 1개당 기본 1장을 넘는 "초과 페이지"에 매기는 비용인데, **봉투 삽입 이벤트 자체가
없는 작업**(반제품 — `data_transform.apply_반제품_logic()`이 건수를 0으로 만든 행 / 제본만 하고
봉투 없이 발송·납품하는 "제본 단독" 작업)에서는 `봉입건수`가 0이 되면서 `장수 - 0` = **장수 전체가
그대로 "초과분"으로 계산**돼버림. 참고로 옛 Streamlit(app.py) 화면의 **표시용** 합계 통계에는 이미
`(총장수>0 and 총봉입>0) else 0` 가드가 있었으나(2026-06-17), 실제 청구 금액을 계산하는 billing.py에는
이 가드가 처음부터 없었음.

## 수정 내용 (완료)

`scripts/billing.py`의 `_작업별_품목누적()`:
```python
배송계열합 = 압착 + 봉입 + 수작업 + 중철 + 제본
삽입기준수량 = (봉입 + 수작업) if 배송계열합 > 0 else 봉입건수
추가용지 = max(0, 장수 - 삽입기준수량) if 삽입기준수량 > 0 else 0
```
- **삽입기준수량이 0이면 추가용지도 0** — 이게 이번 수정의 핵심(기존 가드 누락 보완)
- 신규 데이터(2026-08-21 도입한 공정 세분화 컬럼)가 있으면 "실제 삽입 이벤트"(봉입+수작업)를 기준으로
  삼음(사용자 확정: "추가봉입은 수작업·봉입[기계봉입]에만 해당됨") — 압착·중철·제본만 있고 봉입·수작업이
  둘 다 없는 작업(예: 봉투 없이 그대로 발송/납품)은 추가봉입비 0이 정답(사용자 확인, 2026-08-22)
- 신규 데이터가 없는 배치(과거 데이터)는 기존 `봉입건수` 기준 그대로 사용(단, 0이면 0으로 처리하는
  가드는 동일하게 적용 — 원래 표시용 통계와 같은 규칙으로 통일됨)
- `배송계열합` 변수는 아래 봉입비 계산 블록과 공유(중복 계산 제거)
