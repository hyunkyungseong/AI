# 플랜: 파피(Paffy) 모의고사 / OMR 업무명 구분

> 작성: 2026-11-16 | 상태: **종결 — 코드 수정 불필요 (2026-11-19)**

## 종결 사유 (2026-11-19)
- 사용자 확인: N사업부 교재제작은 시험지 / 답안지(OMR) / 책자(표지+내지) 3종이 **한 의뢰서에 함께 들어갈 수 있고**, 종류마다 **별도 자재**·별도 단가
- 이미 있는 자재별 단가(단가마스터_자재단가, "출력비"·"출력자재비" 코드, 2026-08-16~22 구현)로 의뢰서 안에서 종류별 단가 적용 가능 → 업무명 분리 불필요
- 업무명을 나누면 섞인 의뢰서(로컬 DB 24건)에서 같은 (의뢰서+작업명) 자재가 두 업무명에 이중 집계될 위험 → 오히려 해로움
- 기존 Paffy 단어 규칙(`data_transform.py` 40-43행)은 2026-07-18 최초 커밋부터 있던 것으로 자재별 단가 기능 이전의 방식, 한 번도 작동한 적 없음 — 그대로 둠(정리는 필요 시 별도)
- 아래 원래 계획은 기록용으로 남김

## 배경
- `scripts/data_transform.py` `add_client_column()`의 Paffy 규칙이 한 번도 작동하지 않음
  - 찾는 **칸**이 틀림: `업무명상세`에서 찾지만 키워드는 `작업내역서상세`에 있음
  - 찾는 **단어**가 틀림: "모의고사 시험지" 0행, 실제 표기는 "모의고사"(30행)
- 로컬 DB 집계(사용자 실행, 2026-05-04~08-31): 파피 4,385행 / 의뢰서 511건, 업무명 전부 `파피교재제작`
  - "모의고사" 30행, "OMR" 8행(대소문자 차이 없음)
  - 파피 단가마스터·청구품목규칙·담당자 등록 **0건**, 발행된 파피 거래명세서 **0건**

## 사용자 확정 사항 (2026-11-16)
1. 모의고사와 OMR은 **구분되어야 함**
2. 구분 방법: 업무명 **뒤에 붙이기**
3. 키워드 없는 파피 행: **그대로** (`파피교재제작`)
4. 이미 발행된 파피 거래명세서: **그대로** (바꾸지 않음)
5. 찾는 단어 `모의고사` → 업무명 `파피교재제작 모의고사`
6. 한 행에 둘 다 있으면 **OMR 우선** → `파피교재제작 OMR`
