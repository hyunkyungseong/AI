# 버그: 조가 없는 거래명세서 — "요청내용" 표지 "품목"이 B12 직접입력값을 안 따름

> 상태: ✅ 완료(2026-11-12) — 코드 수정·검증·사용자 화면 확인·커밋·사무실 PC 배포까지 전부 완료.
> 배포 이력: `.claude/plans/plan_2026-11-12_사무실PC배포체크리스트.md`
> 발견: 2026-09-15 작업("조 없는 거래명세서에도 B12 업무명 직접 입력") 화면 확인 중 사용자 확인
> (삼성화재해상보험(주) · 내용증명 4종 — B12에 "아무거나" 입력 → 시트 B12는 정상 반영, 표지 품목은 원래 업무명으로 표기)

## 무슨 문제인가 (쉬운 설명)
엑셀 파일 맨 앞장("요청내용" 표지)의 "품목" 칸은 2026-08-30에 **"항상 거래명세서 시트 상단(B12)과
똑같이 맞춘다"**는 원칙을 정했다. 조가 여러 개인 경우(조별표지·통합시트)는 그때 이 원칙대로 고쳐뒀지만,
2026-09-15에 새로 생긴 **"조가 없는 평범한 거래명세서에도 B12를 직접 입력"** 경우는 이 원칙이 빠져 있어,
표지에는 여전히 확정 당시 저장된 원래 업무명(`거래명세서.품목`)이 들어간다.

## 원인 (근거)
- `scripts/api.py` `_거래명세서_엑셀_시트목록()` — 표지 품목 초기값이 `거래명세서["품목"]`(1014행)
- 덮어쓰기는 두 곳뿐: 조별표지(1133행, 조 2개 이상) / 통합시트(1170행, 조 2개 이상)
- 시트가 1장뿐인 경우(조 없음 또는 조 1개)는 덮어쓰기가 없음 → 원래 업무명 그대로

## 수정 계획 (`scripts/api.py` 1곳, 2~3줄)
시트가 딱 1장인 경우(`len(그룹순서) == 1`), 표지 품목을 그 시트의 B12 값으로 덮어쓴다.
B12 값은 바로 위 반복문에서 이미 읽어 `조별표지_목록[0]["품목"]`에 담아두므로 **새로 읽지 않고 재사용**
(조별표지·통합시트 때와 같은 원리, 엑셀을 한 번 더 열지 않음).

```python
if len(그룹순서) == 1:
    표지정보["품목"] = 조별표지_목록[0]["품목"]
```

- B12를 비워둔 경우: B12에 원래 업무명이 자동으로 들어가므로 표지도 지금과 똑같이 나옴 → **기존 동작 변화 없음**
- 조가 여러 개인데 통합시트·조별표지 둘 다 아닌 경우: 시트가 여러 장이라 어느 B12를 쓸지 정할 수 없어 **이번 범위에서 제외**(지금처럼 원래 업무명 유지)
- DB 변경 없음, 화면(프론트엔드) 변경 없음

## 이미 발행된 건은?
표지는 저장된 파일이 아니라 **다운로드할 때마다 새로 만들어지므로**, 수정 후 다시 다운로드하면 이번 테스트 건도
자동으로 올바르게 나온다(별도 데이터 정정 불필요).

## ⚠️ 구현 중 설계 보정 (2026-11-12, 검증 중 발견)
위 "B12를 무조건 따라감" 방식으로 회귀 검증을 돌리자 **D-202608-00088(KB증권)** 표지 품목이 "거래원장" → "None"으로
망가지는 것을 발견 — 이 건의 의뢰서(93362)가 원본 데이터 교체(5~7월 자료)로 운영통계자료에서 빠져 B12 자동값
자체가 "None"인 옛 건이었음(B12 "None"은 이번 수정과 무관한 기존 상태). 그래서 **"사용자가 B12를 직접
입력한 경우에만"** 표지 품목을 그 값으로 덮어쓰도록 좁힘(`거래명세서_품목.조상단업무명`이 있을 때만) —
직접입력이 없으면 표지는 기존과 100% 동일.
