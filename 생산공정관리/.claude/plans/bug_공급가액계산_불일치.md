# 버그 수정: 미발행목록 "예상공급가액" ≠ 발행요청목록 "청구공급가액" 불일치 — ✅ 코드 수정·검증·사무실 PC 배포 전부 완료 (2026-08-20)

## Context (왜 필요한가)

사용자가 미발행 목록의 "예상공급가액"(KB증권 의뢰서 93362, 26.03월: 10,995,284원)과, 같은 항목을
"거래명세서 요청"한 뒤 발행요청목록에 뜨는 "청구공급가액"(원본, 조건식 미적용: 11,203,574원)이
208,290원 차이 나는 걸 스크린샷으로 제보.

**원인**: `scripts/billing.py`의 공급가액 계산 함수가 두 개(`calc_공급가맵()`·`build_품목행()`)로
나뉘어 있었는데, 2026-08-17 "출력비·봉입비 자재사용량 기준 전환"(자재 종류별 개별 등록 단가,
인쇄면 배율, `_자재비례배분_처리()`/`_자재별_처리()`)이 `build_품목행()`(미리보기·실제 확정·저장
시 사용)에만 반영되고 `calc_공급가맵()`(미발행목록·발행목록·예상공급가액·부분취소 화면에서 사용)은
옛날 단순 곱셈 방식 그대로 남아있었다. 이번 KB증권 사례는 "거래원장 각대봉투"(자재코드 414)에
개별 등록된 단가(130원, 기본단가 24원보다 높음)가 `calc_공급가맵()`에는 반영되지 않아 생긴
**과소 청구**였다(로컬 MariaDB로 재현해 정확히 208,290원 차이·원인 확정).

**⚠️ 화면 표시 문제를 넘어선 실제 금액 버그**: `scripts/api.py`의 부분취소 API(당시 2464행)가
이 옛날 `calc_공급가맵()` 재계산값을 그대로 `거래명세서.공급가액`에 덮어쓰고 있었다 — 정확했던
거래명세서를 부분취소하면 남은 금액이 부정확한 값으로 바뀌는 실제 청구 오류였다.

## 수정 내용

### `scripts/billing.py`
- `build_품목행()`의 품목별 금액 계산 로직(출력비·봉입비·출력자재비·봉입자재비·추가봉입비·
  동봉물삽입비·삽지비, 옛 289~343행)을 `_작업별_품목누적()`이라는 공유 함수로 추출(로직 변경 없음,
  위치만 이동).
- `build_품목행()`은 이 함수를 호출하도록 수정(여러 의뢰서를 미리 하나로 합쳐서 넘기는 기존
  로직은 그대로 유지).
- `calc_공급가맵()`을 다시 작성해 같은 함수를 호출 — 미발행목록 화면이 의뢰서별 개별 금액을
  보여줘야 하므로, 의뢰서를 합치지 않고 **의뢰서 1건씩** 계산하는 기존 구조는 유지.
- `calc_공급가맵()`에 "청구페이지있음"(사람이 직접 확인한 청구페이지가 있는지) 판정을
  `build_품목행()`과 동일하게 추가.

### `scripts/api.py`
- SELECT 문에 "청구페이지" 컬럼 추가 4곳: `GET /예상공급가액`·`GET /미발행목록`·`GET /발행목록`·
  부분취소 API — `calc_공급가맵()`/`build_품목행()`이 "청구페이지있음" 판정을 하려면 필요.
- 부분취소 API의 재계산 함수를 `calc_공급가맵()`에서 `build_품목행()`으로 교체(여러 의뢰서를
  하나의 거래명세서 금액으로 합칠 때는 실제 확정 시점과 완전히 같은 함수를 써야 오차가 구조적으로
  없어짐).

## 검증 결과 (완료)

1. `python -m py_compile scripts/billing.py scripts/api.py scripts/app.py` 통과.
2. **KB증권 93362 재현**: 수정 전 `calc_공급가맵` 10,995,284원 vs `build_품목행` 11,203,574원
   (차액 208,290원) → 수정 후 두 함수 모두 11,203,574원으로 정확히 일치. 항목 단위로도 확인 —
   차이는 "봉입자재비"(각대봉투 1,965개×130원 + 나머지 63,404개×24원=1,777,146원)가
   `calc_공급가맵()`에서 이제 정확히 반영됨(수정 전엔 65,369개 전부 기본단가 24원으로만 계산해
   1,568,856원으로 과소 청구되고 있었음).
3. **로컬 MariaDB 전수/샘플 회귀 검증**(자재단가 등록 거래처 전수 1,187건 + 랜덤 샘플 500건,
   총 1,687건): 기존 `calc_공급가맵()`(수정 전 코드)과 신버전을 비교 — **1,467건 변경없음**(회귀
   없음 확인), **220건 의도된 변경**(자재단가·인쇄면 배율 등이 이제 올바르게 반영됨), 신버전
   `calc_공급가맵()`과 `build_품목행()`의 **불일치 0건**(1,687건 전부 정확히 일치).
4. 로컬 API 서버(포트 8000) 재시작 완료(`py -3.12 scripts/api.py`, `/health` 응답 정상).

## 참고 — 구조적으로 남는 한계 (문제 없다고 판단)
미발행목록·발행목록은 의뢰서를 항상 낱개로 보여주므로, 한 작업명 안에서 의뢰서마다 자재 사용
비율이 다르고 "사람이 직접 확인한 청구페이지"가 있는 아주 좁은 경우엔 "의뢰서별 개별 계산 후
합산"과 "여러 의뢰서를 하나로 묶어 계산"이 수학적으로 100% 일치하지 않을 수 있음(자재비례배분의
비율 정규화 특성상). 다만 실제 확정 순간에는 항상 `build_품목행()`(정확한 계산)이 다시 쓰이므로
실제 청구 금액에는 영향 없음 — 미확정 미리보기 화면의 근사치 차이일 뿐.
