## 참고 — 자재사용현황 갱신 관련
`preprocess.py`는 `운영통계자료`·`자재사용현황` 테이블을 **통째로 비우고(TRUNCATE) 로컬 엑셀 파일
기준으로 다시 채우는** 방식입니다. 원래는 사무실 PC가 당사 생산공정관리시스템 실시간 API로 계속
데이터를 받는 구조라 이 방식이 위험할 수 있지만, **사무실 PC는 현재 테스트 단계라 실시간으로 받은
자료가 없다고 확인해주셔서(2026-08-24) 이번엔 안전하게 4단계를 그대로 진행하시면 됩니다.**
(나중에 실제 운영 전환 후 다시 이런 재적재가 필요해지면, 그때는 실시간 수신 데이터가 로컬 엑셀보다
앞서 있는지 먼저 확인하고 백업 테이블부터 만들어두는 절차가 다시 필요합니다 — 참고로만 남겨둡니다.)

## 1단계 — 코드 파일 복사
로컬 PC의 아래 3개 파일을 사무실 PC의 같은 경로(`scripts/`)로 덮어씁니다.

- `scripts/api.py`
- `scripts/init_db_mariadb.py`
- `scripts/preprocess.py`

**`billing.py`·`data_transform.py`는 이번엔 대상 아님**(안 바뀜).
**프론트엔드는 배포 대상 아님** — 화면은 로컬 PC의 Next.js가 `frontend/.env.local`의 `FASTAPI_URL`로
사무실 PC를 가리켜 그대로 씁니다(파일 복사 불필요).

## 2단계 — DB 마이그레이션 실행
사무실 PC에서:
```
cd 프로젝트폴더
python scripts/init_db_mariadb.py
```
→ 콘솔에 `마이그레이션: 거래처마스터.역발행 컬럼 추가 완료`가 뜨면 성공. (다른 마이그레이션은 전부
"이미 존재 (건너뜀)"으로만 나와야 정상 — 8/23까지 이미 전부 반영된 상태이기 때문)

## 3단계 — API 서버 재시작
1. 기존에 떠 있는 API 서버 창을 닫거나 Ctrl+C로 종료(포트 8001)
2. `API서버_실행_사무실PC.bat` 다시 실행
3. 브라우저에서 `http://localhost:8001/health` 접속 → 정상 응답 확인

여기까지만 하면 **"역발행" 기능은 사무실 PC에 완전히 반영된 상태**입니다. 자재사용현황 갱신이
필요 없으면 여기서 멈추고 아래 "배포 후 확인"으로 건너뛰세요.

## 4단계 — 자재사용현황 5~7월 자료 갱신

### 4-1. 엑셀 파일 복사
로컬 PC의 아래 2개 파일을 사무실 PC의 `data/` 폴더로 복사합니다(USB나 사내망 공유 등).
- `data/운영통계자료.xlsx`
- `data/자재사용현황.xlsx`

### 4-2. 재적재 실행
```
python scripts/preprocess.py
```
콘솔에 아래처럼 나오면 정상입니다.
```
[load_자재_raw] 자재종류 결측 7건 제외
...
MariaDB 운영통계자료: 26,774건 반영 완료
MariaDB 자재사용현황: 12,717건 반영 완료
```

### 4-3. 결과 확인
```sql
SELECT COUNT(*) FROM 자재사용현황;                 -- 12,717이어야 함
SELECT MIN(작업일자), MAX(작업일자) FROM 자재사용현황;  -- 2026-05-04 ~ 2026-07-30
```
숫자가 다르게 나오면 진행을 멈추고 알려주세요.
