## ⚠️ 선행 분석 필요: 단가 구조 재설계

현재 거래처마스터는 **거래처명 단위**로 단일 단가 세트를 보유합니다.
실제 업무는 **고객사 → 계약 → 업무 → 작업** 계층 단위로 단가가 다르게 배정됩니다.

### 현재 구조 (변경 전)
```
거래처마스터
├── 거래처명 (PK)
├── 출력단가
├── 봉입단가
├── 추가봉입단가
├── 용지제작단가
└── 봉투제작단가
```

### 목표 구조 (변경 후)
```
고객사 단위 기본 정보
├── 고객사명
├── 고객사코드
├── 사업자등록번호
└── 수신이메일

단가 테이블 (계층 구조)
├── 고객사명 (FK)
├── 계약명          ← 운영통계자료의 어떤 필드와 매칭되는지 확인 필요
├── 업무명          ← 운영통계자료 "업무명" 필드
├── 작업명          ← 운영통계자료 "작업명" 필드
├── 출력단가
├── 봉입단가
├── 추가봉입단가
├── 용지제작단가
└── 봉투제작단가
```

### 확인 필요 사항 (관리자 답변 대기)
- [ ] A. 운영통계자료의 어떤 필드가 "계약명"에 해당하는가?
      (업무의뢰서번호? 업무명? 별도 계약코드 필드?)
- [ ] B. 단가가 다른 경우의 실제 예시 (같은 고객사인데 업무명에 따라 단가가 다른 케이스)
- [ ] C. 단가 일치 우선순위: 고객사+업무명+작업명 → 고객사+업무명 → 고객사 순으로 fallback 적용 여부
