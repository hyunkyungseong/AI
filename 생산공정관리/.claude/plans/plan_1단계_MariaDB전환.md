## 확정된 방향 (2026-07-19)

| 항목 | 결정 |
|---|---|
| FastAPI·MariaDB 서버 위치 | 사무실 PC 계속 사용 (최종) |
| 보안 | 사내 전용, 로그인 필요 |
| 전환 방식 | 점진적 (Streamlit 유지 + 탭 단위로 Next.js 교체는 별도 플랜에서 진행) |

## 구조 변경 요약

```
[현재]
Streamlit app.py → sqlite3·pkl 직접 접근

[변경 후]
Streamlit app.py → requests → FastAPI(api.py, port 8000) → MariaDB
                                     ↑
                        나중에 Next.js(Vercel)도 여기로 붙음
```

## [4단계] Streamlit → API 호출 방식으로 교체 — ⏸ 보류 (2026-07-19, Next.js로 방향 전환)

> **결정:** app.py를 API 호출 방식으로 뜯어고치는 작업(11~15번)과 Next.js를 처음부터 새로 만드는 작업은 규모가 비슷한데, 후자가 최종 목표에 바로 기여하므로 **이 단계를 건너뛰고 Next.js 프론트엔드로 직행**하기로 함. Streamlit(`app.py`)은 지금 상태(SQLite/pkl 직접 접근) 그대로 손대지 않고 유지. 상세 계획은 `plan_5단계_Next.js프론트엔드.md` 참고.
> **⚠️ 데이터 이원화 주의:** 당사 생산공정관리시스템이 `/운영통계자료수신`으로 **MariaDB에만** 실시간 데이터를 보내는 반면, Streamlit은 여전히 SQLite/pkl만 봄 — 두 화면의 숫자가 시간이 지나며 서서히 달라질 수 있음 (의도된 "당분간 병행" 상태, KNOWLEDGE.md 참고). Next.js 탭이 하나씩 완성될 때마다 해당 영역은 MariaDB 기준으로 통일됨.
> 시도했던 시작 코드(로그인 화면·API 클라이언트 헬퍼 초안)는 사용자 판단으로 반영 보류·폐기함 — app.py는 수정되지 않은 상태.
