# 버그: 표 헤더(thead) sticky 위치 오류 — ✅ 해결됨

> 상태: ✅ 해결 완료 (2026-07-19) — 상세 내용은 `SKILL.md`의 SKILL-16 "확장 — 표 `<thead>`까지 이어붙여 고정하기" 섹션으로 이관됨

## 요약

탭4(거래명세서 관리)의 미발행목록·발행요청목록·발행완료 3개 화면에서 표 컬럼 헤더(`<thead>`)가 제목 블록 바로 아래가 아니라 화면 중간에 떠서 렌더링되던 버그.

**원인:** 표를 감싼 `overflow-x-auto` wrapper div가 CSS 스펙상 "가장 가까운 스크롤 조상"이 되어, `<thead>`의 `position: sticky`가 창(window) 스크롤이 아니라 그 wrapper를 기준으로 계산되고 있었음. wrapper 자신은 내부적으로 스크롤되지 않으므로, thead는 wrapper 상단에서 고정 오프셋만큼 떨어진 자리에 머문 채 창 스크롤을 그대로 따라 흘러가 버렸음(Playwright로 스크롤 전/후 좌표를 실측해 확정).

**해결:** 표를 감싼 wrapper div를 `max-height` + `overflow-auto`(가로·세로 모두)를 가진 독립 스크롤 박스로 만들고, thead를 그 박스 자기 자신 기준 `top: 0`으로 붙임 — 박스 자신이 실제로 스크롤되는 조상이 되므로 sticky가 정확히 동작함. `ResizeObserver`로 제목 높이를 측정해 thead에 넘겨주던 `stickyTop`/`useElementHeight` 관련 코드는 전부 제거됨(더 이상 필요 없음).

**트레이드오프:** 표 영역이 페이지 전체와 하나로 이어지는 스크롤이 아니라, 표마다 자체 스크롤바를 가진 독립 박스가 됨(사용자 확인 후 채택 — JS로 직접 계산하는 대안보다 안정적).

이 문제를 다시 만나면(다른 화면에 sticky thead를 새로 추가할 때 등) `SKILL.md` SKILL-16을 먼저 참고할 것 — 원인 진단 방법과 최종 채택 패턴이 기록돼 있음.
