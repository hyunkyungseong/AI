# 버그: 거래명세서 품목 수정이력 — 같은 품명이 여러 "조"에 걸치면 누락

> 상태: ✅ 완료(2026-09-03) — 코드 수정·실데이터 검증·사무실 PC 배포까지 전부 완료.
> 상세 배포 이력: `.claude/plans/plan_2026-09-03_사무실PC배포체크리스트.md`

## 문제
D-202609-00002(BC카드)에서 "출력페이지" 품목 중 "우리" 조(은행)의 수량을 수정했는데, 공급가액·
세액·합계는 정상 기록됐지만 품목 단위 "수량"·"금액" 수정이력 로그가 누락됨.

## 원인
BC카드처럼 같은 업무명 조합이 여러 "조"(은행별 등)로 나뉘는 거래처는 같은 품명("출력페이지" 등)이
조마다 하나씩 반복된다. `scripts/api.py`의 `_품목_변경_이력()` 매칭 키가 `(코드, 표시품명)`뿐이라
"조"가 빠져 있어, 여러 조의 같은 품명 행이 전부 같은 키로 뭉쳐지고 — 비교 로직이 그 그룹의
**첫 번째 행만** 비교해 나머지 조의 변경은 조용히 무시됐다. (참고: 공급가액·세액·합계는 전체
품목을 순서대로 리스트 비교하는 별도 로직이라 이 문제가 없었음 — 실제 청구 금액은 처음부터
정확했고, 감사이력 상세 로그만 빠진 것이었음)

**1차 진단(오진, 폐기)**: 처음엔 "조건식이 등록 안 돼서(효과_규칙목록 비어있음)"로 추정했으나,
DB 직접 조회 결과 BC카드에는 조건식이 32건 정상 등록돼 있어 오진단으로 확인·정정함(사용자 지적).

## 수정
`scripts/api.py`의 `_품목_변경_이력()` 매칭 키에 `"조"` 추가:
```python
def _키(r):
    return (r.get("코드") or "", r.get("표시품명") or "", r.get("조") or "")
```

## 검증
`구분='기준'` 스냅샷이 있는 전체 확정 건(5건, 2026-08-18 기능 도입 이후 전부)을 신/구 버전 함수로
전수 비교 — 3건 완전 동일(회귀 없음), 2건에서 기존에 조용히 누락되던 진짜 수정 건이 정확히
새로 감지됨(D-202609-00002: 수량+금액 2건, D-202609-00001: 양식지/출력페이지/추가봉입 등 5개
필드 10건 — 순변동 합계가 기존 공급가액 차이와 정확히 일치함을 확인). `python -m py_compile` 통과.
사용자가 실제 브라우저에서 새 확정 건으로 재확인 완료.

## 백필하지 않기로 한 과거 건
D-202609-00002는 이 수정 이전 확정 건이라 수정이력에 "수량"·"금액" 2건이 빠진 채 과거 기록
유지(2026-09-03 사용자 결정 — 실제 청구 금액은 처음부터 정확했음). 이 수정은 이후 신규 확정
건부터만 적용됨.
