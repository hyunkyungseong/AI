# 2026-08-30 사무실 PC 배포 체크리스트 — 조별표지 분리 + 조상단업무명

> 상태: ✅ 배포 완료(2026-08-30) — 사용자 브라우저 확인 완료. "추가 수정분"(통합 명세서 품목
> B12 반영)까지 전부 사무실 PC 반영 완료. 로컬·사무실 PC 코드·DB 동기화 상태, 남은 미배포 항목 없음.

> 오늘 완료된 두 기능(조별표지분리, 조상단업무명) + 관련 버그 수정 전부를 사무실 PC에 배포합니다.
> **이번엔 DB 구조 변경(마이그레이션)이 있습니다** — 코드 파일 복사 후 마이그레이션 스크립트도
> 반드시 실행해야 합니다.

## 오늘 작업 요약

1. **조별표지분리** (`.claude/plans/plan_조별표지분리.md`) — 거래처마스터에 "조별표지" 체크박스
   신설. 체크된 거래처는 작업구분(조)이 2개 이상이어도 통합 명세서를 만들지 않고, "요청내용" 표지에
   조별 부분합을 2개씩 가로로(3개 이상이면 아래로 이어서) 나눠 보여줍니다.
2. **조상단업무명** (`.claude/plans/plan_조상단업무명.md`) — 개별 조 시트 상단(B12)에 자동으로
   들어가던 업무명을, 미리보기 화면의 각 "작업구분" 그룹 헤더에서 사용자가 직접 입력/수정할 수
   있게 함(비워두면 기존처럼 자동).
3. **버그 수정 2건**(실사용 검증 중 발견) — ① 거래처마스터 "조별표지" 체크박스가 저장 시 DB에
   실제로는 반영 안 되던 문제(Pydantic 모델·SQL문 누락) ② 표지 "품목" 필드를 라인아이템 조합 대신
   그 조 시트의 B12 값을 그대로 읽어오도록 수정 + "거래명세서번호" 빈칸 → 공통값 표시로 수정.
4. **표시 형식 통일** — 조별표지 표지의 "비고" 칸도 기존 단일 표지와 동일하게
   `시트참조(시트명)` 형식으로 통일.

## 1단계 — 코드 파일 복사

로컬 PC의 아래 3개 파일을 사무실 PC의 같은 경로(`scripts/`)로 덮어씁니다.

- `scripts/api.py`
- `scripts/billing.py`
- `scripts/init_db_mariadb.py`

**프론트엔드 파일은 복사할 필요 없습니다** — 화면은 로컬 PC의 Next.js가 그대로 담당하고,
`frontend/.env.local`의 `FASTAPI_URL`로 사무실 PC를 가리켜 씁니다.

## 2단계 — DB 마이그레이션 실행 (이번엔 꼭 필요)

사무실 PC에서:
```
python scripts/init_db_mariadb.py
```
아래 내용이 반영됩니다(전부 기존 데이터에 영향 없는 추가뿐 — 회귀 없음):
- `거래처마스터.조별표지` 컬럼 추가(기존 거래처 전부 0=꺼짐으로 채워짐)
- `거래명세서_품목.조상단업무명` 컬럼 추가(기존 행 전부 NULL)
- `조상단업무명설정` 신규 테이블 생성

마이그레이션 로그에 "컬럼 추가 완료"/"테이블 생성 완료"가 찍히는지 확인하세요(이미 실행한 적
있으면 "이미 존재 (건너뜀)"이 뜨는 게 정상입니다).

## 3단계 — API 서버 재시작

1. 기존에 떠 있는 API 서버 창을 닫거나 Ctrl+C로 종료(포트 8001)
2. `API서버_실행_사무실PC.bat` 다시 실행
3. 브라우저에서 `http://localhost:8001/health` 접속 → 정상 응답 확인

코드·DB 반영은 여기까지입니다. 아래 4단계부터는 브라우저로 실제 확인하는 단계입니다.

---

## 4단계 — 조별표지 재설정 확인 (브라우저)

[거래처 마스터] → 삼성화재해상보험(주) [수정] → "조별표지" 체크 → 저장
→ 예상 결과: 목록의 "설정" 칸에 "조별표지" 배지가 떠야 함(마이그레이션 직후라 사무실 PC DB에는
  이 값이 꺼져 있는 상태로 시작하므로, 로컬 PC에서 했던 것처럼 다시 체크해야 합니다)

## 5단계 — 조상단업무명 입력 확인 (브라우저)

조가 2개 이상인 그 거래처로 [거래명세서 관리] → "거래명세서 요청" 클릭
→ 예상 결과: 통합시트명 입력칸 대신 "조별표지 대상" 안내문이 보이고, 각 "작업구분" 그룹 헤더
  줄에 "시트 상단 업무명" 입력칸도 함께 보여야 함

## 6단계 — 확정·다운로드 결과 확인 (브라우저)

각 작업구분에 서로 다른 상단 업무명 입력 후 확정 → 다운로드
→ 예상 결과: "요청내용" 표지에 조별 부분합이 2개씩 나란히(3개 이상이면 아래로 이어서) 표시되고,
  각 블록의 "품목"이 입력한 상단 업무명과 일치, "거래명세서번호"도 양쪽에 채워져 있어야 함,
  "비고"는 `시트참조(시트명)` 형식이어야 함

## 7단계 — 회귀 확인 (브라우저)

조별표지 미체크 거래처(기존 방식)로도 하나 테스트
→ 예상 결과: 기존과 완전히 동일하게 동작(통합시트명 입력칸 그대로 보이고, 회귀 없어야 함)

❌ 오류 시: 빨간색 오류 메시지를 캡처하거나 내용을 그대로 복사해서 알려주세요.

## 추가 수정분 — 통합 명세서 "품목" B12 반영 (같은 날 후속)

7단계까지 배포·검증한 뒤, 사용자가 BC카드 건(조별표지 아닌 "통합 명세서" 케이스)에서 표지
"품목"이 여전히 확정 시점 구식 업무명 조합으로 나온다고 제보 — 조별표지 때와 동일하게, 통합
시트에 실제로 적힌 B12 값을 그대로 읽어와 쓰도록 `scripts/api.py`(1161~1165행 부근, 통합바이트
생성 직후) 한 줄 추가 수정. **DB 마이그레이션 불필요, `scripts/api.py` 파일 재복사만 하면 됩니다.**

### 배포 방법
1. 로컬 PC의 `scripts/api.py`를 사무실 PC의 같은 경로로 다시 덮어씀(위 1단계와 동일 파일, 최신본으로 교체)
2. 기존 API 서버 창 종료(포트 8001) → `API서버_실행_사무실PC.bat` 재실행
3. `http://localhost:8001/health` 정상 응답 확인

### 확인할 것
- 조가 2개 이상이고 조별표지가 **아닌**(통합 명세서 쓰는) 거래처(예: BC카드)의 거래명세서를 다운로드
  → 예상 결과: "요청내용" 표지의 "품목"이 통합 시트 상단(B12)에 실제로 적힌 값과 정확히 일치해야 함
  (예전처럼 업무명이 쉼표로 어색하게 나열되던 문제가 사라져야 함)
