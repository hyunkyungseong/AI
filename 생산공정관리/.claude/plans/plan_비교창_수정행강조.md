# 비교 창에서 사람이 고친 행 강조 표시

> 상태: ✅ 완료 — 사무실 PC 배포까지 (2026-11-15)
> 출발 메모: `.claude/plans/plan_다음작업_수정행강조_창이동.md` 요청 1
> 대상 화면: 발행요청목록·발행완료(+수정이력 탭)에서 배지를 누르면 뜨는 "원본 vs 최종 비교" 창 (`frontend/components/InvoiceHistoryDialog.tsx`)

## 사용자가 정한 기준 (2026-11-15)
- **원본** = 조건식으로 자동 계산된 결과 (비교 창 왼쪽 표)
- **수정된 행** = 그 원본을 사용자가 직접 고친 행
- 표시 방법
  - 고친 행: 오른쪽(최종) 표에서 행 전체를 연한 노랑으로 칠합니다. 바뀐 칸은 굵은 빨간 글씨로 쓰고, 옆에 이전 값을 `(320)`처럼 작게 붙입니다.
  - 추가한 행: 오른쪽 표에서 초록 배경에 `추가` 표시를 붙입니다.
  - 지운 행: 왼쪽(원본) 표에서 회색 취소선에 `삭제` 표시를 붙입니다.

## 근거 (코드 확인 결과)
- 비교 창 왼쪽 표는 "조건식 적용 후·사람이 손대기 전" 사진(`기준` 스냅샷)을 보여 줍니다. 2026-08-18 이후 발행 건만 해당합니다. (`scripts/api.py` `거래명세서품목이력()`)
- 확정할 때 남는 품목 수정이력도 같은 두 표(기준 ↔ 최종)를 비교해 만듭니다. (`_품목_변경_이력(기준목록, 최종목록)`)
  - 행 짝짓기 기준: **코드 + 품목명 + 조**
  - 비교하는 칸: 수량·단가·금액
- 그래서 같은 짝짓기 기준을 쓰면 **수정이력 목록과 강조 표시가 항상 일치**합니다. (SKILL-42: 같은 계산을 두 곳에서 따로 만들지 않기)

## 비유로 보는 방법
- 서버가 두 장의 사진(원본·최종)을 겹쳐 보고 행마다 꼬리표를 붙여서 보냅니다.
  - 꼬리표 종류: "고침(무엇이 얼마에서)", "새로 추가", "지워짐"
- 화면은 그 꼬리표대로 색만 칠합니다.
- 화면이 따로 비교하지 않으므로, 수정이력과 판정이 어긋날 일이 없습니다.
