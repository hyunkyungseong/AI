# 거래명세서 — 작업구분(조)별 멀티 시트 발급 시 맨 앞에 "통합 명세서" 시트 추가

## 사용자 요청 원문 (2026-08-12)

> "작업구분에 따라 멀티 명세서가 생기는 업무는 맨 앞 시트에 멀티명세서 통합 명세서가 생성되어야 함"

## 현재 상태 (파악 필요 — 아래는 이전 세션 기억 기준, 코드로 재확인할 것)

- "작업구분"은 화면 라벨이고 내부적으로는 "조"(`청구품목규칙.조`, `거래명세서_품목.조`) — 하나의 거래명세서가 조 값 기준으로 여러 시트로 나뉘어 다운로드되는 기능은 이미 있음(2026-07-29~08-01, `.claude/plans/plan_거래명세서_조별분할발급_통합엑셀.md` 참고).
- 관련 함수: `scripts/billing.py`의 `combine_거래명세서_시트들()`(여러 개의 단일시트 xlsx를 하나의 다중시트 워크북으로 합침, SKILL-29 참고), `scripts/api.py`의 `_거래명세서_엑셀_시트목록()`(거래명세서_품목을 조 값으로 그룹핑해 시트별 바이트 목록 생성)와 `GET /거래명세서엑셀/{no}`(최종적으로 이 둘을 조합해 다운로드 응답 생성).
- 지금은 조 개수만큼 시트가 생기고, 각 시트가 그 조에 속한 품목들의 소계만 보여주는 구조로 추정됨(맨 앞에 전체를 합친 요약 시트는 없음) — **이 부분을 다음 세션에서 코드로 직접 재확인할 것**.

## 다음 세션 시작 시 할 일 (제안 — 실제 착수 시 사용자와 다시 확정)

1. `scripts/billing.py`의 `combine_거래명세서_시트들()`·`write_거래명세서_excel()`, `scripts/api.py`의 `_거래명세서_엑셀_시트목록()`을 다시 읽어 "지금 멀티 시트 발급이 정확히 어떻게 동작하는지"부터 재확인(Read-only).
2. "통합 명세서"가 정확히 뭘 의미하는지 사용자와 확인 — 예를 들어:
   - 전체 조를 합친 품목 전체 목록 1장(개별 시트들의 소계가 아니라 전체 원본 품목이 다 나열된 형태)?
   - 아니면 각 조별 소계만 요약한 "목차성" 표(조 이름 + 그 조의 합계 금액만 나열된 요약표)?
   - 실제 회계·거래명세서 서식 관행상 어느 쪽이 맞는지 사용자에게 예시(스크린샷 등)를 요청해 확인.
3. 템플릿(`data/거래명세서_템플릿_base.xlsx`)에 "통합 명세서" 전용 시트 서식이 이미 있는지, 아니면 기존 품목 시트 서식을 재사용/변형해서 만들어야 하는지 확인.
4. 조가 1개뿐이거나(=시트 분할 자체가 없는 경우) 조가 아예 없는 기존 방식(하위호환)에는 이 통합 시트를 안 만드는 게 맞는지도 확인(조 2개 이상일 때만 의미가 있을 가능성이 큼 — `InvoicePreviewDialog.tsx`의 "분할표시" 조건, `조_그룹목록.length > 1`과 동일한 기준일 수 있음).
5. 설계 확정 후 Plan 작성 → 사용자 승인 → 구현 → 로컬 검증 → 화면 테스트 체크리스트 제공 순서로 진행(이 프로젝트 표준 절차).
