# 사무실 PC 배포 체크리스트: v0.10.0 (고객 제출용 명세서)

> 상위 계획: `.claude/plans/plan_고객제출용명세서.md` (7단계)
>
> 상태: ⏳ 준비 중 — 로컬 화면 확인 → 버전 올림·커밋 → 묶음 생성 후 진행
> 소요 시간: 약 20~25분(화면 조립 시간 포함)
> **DB 변경 있음** — 2단계에서 마이그레이션을 꼭 실행합니다(빠뜨리면 거래처 목록·확정이 오류).

## 이번 배포로 바뀌는 것
1. 거래처관리 편집 창에 **"고객 제출용 명세서 사용"** 체크가 생깁니다(처음엔 모든 거래처 꺼짐 → 켜기 전엔 아무것도 안 바뀜).
2. 켠 거래처는 미리보기 [확정 → 고객 제출용 편집] 다음에 고객용 편집창이 뜹니다.
3. 발행요청목록에 주황 [고객용 편집] / 빨강 [고객용 재편집 필요] 버튼이 보입니다.
4. 엑셀 다운로드 맨 앞에 `고객 제출용` 시트가 들어갑니다(고객용 줄이 있는 건만).
5. 모든 명세서 공통: B12·품명·표지 품목이 칸보다 길면 셀 안에서 줄바꿈됩니다.

## 0단계 — 준비물
- [ ] 로컬 PC의 `output\배포_v0.10.0` 폴더를 USB에 통째로 복사합니다.
  - 들어 있는 것: `scripts\api.py`·`billing.py`·`init_db_mariadb.py`·`version.py`, `frontend`, 이 체크리스트
  - 빠져 있는 것: 비밀 설정 파일(`frontend`의 환경 설정 파일·`db_config.py`), `node_modules`, `.next`

## 1단계 — 서버 백업·복사
- [ ] 사무실 PC `scripts` 폴더에서 아래 4개를 복사해 이름을 바꿔 둡니다.
  - `api.py` → `api.py.bak_v0.9.0`
  - `billing.py` → `billing.py.bak_v0.9.0`
  - `init_db_mariadb.py` → `init_db_mariadb.py.bak_v0.9.0`
  - `version.py` → `version.py.bak_v0.9.0`
- [ ] USB `scripts` 폴더의 파일 4개를 사무실 PC `scripts` 폴더에 **덮어쓰기** 합니다.
  - ❗ `db_config.py`는 복사하지 않습니다.

## 2단계 — DB 마이그레이션(표·칸 추가) ❗ 꼭 실행
- [ ] 프로젝트 폴더에서 명령 창을 열고 아래를 실행합니다.
  ```
  python scripts/init_db_mariadb.py
  ```
- [ ] 오류 없이 끝나는지 봅니다. 추가되는 것(기존 데이터는 안 건드림, 여러 번 실행해도 안전):
  - 칸: `거래처마스터.고객제출용`, `거래명세서.고객용_재편집필요`
  - 표: `고객제출용규칙`, `거래명세서_고객품목`
  - 글자가 깨져 오류가 나면 `set PYTHONIOENCODING=utf-8` 을 먼저 입력하고 다시 실행합니다(다시 실행해도 안전).

## 3단계 — API 서버 재시작
- [ ] `API서버_재시작_사무실PC.bat`을 더블클릭합니다.
- [ ] 브라우저에서 `http://localhost:8001/health` → **`"status":"ok"` 와 `"version":"0.10.0"`** 확인

## 4단계 — 화면(frontend) 반영
- [ ] 웹 화면 창(포트 3000의 검은 창)을 **먼저 닫습니다.**
- [ ] 사무실 PC의 `frontend` 폴더 이름을 **`frontend_old_v0.9.0`**으로 바꿉니다.
- [ ] USB의 `frontend` 폴더를 프로젝트 폴더에 붙여 넣습니다.
- [ ] `frontend_old_v0.9.0` 안의 **`.env.local`** 파일을 새 `frontend`에 **복사**합니다(숨긴 항목 표시 필요할 수 있음).
- [ ] (확인) 새 `frontend` 안에 `.env.local`, `components\CustomerSheetEditor.tsx`가 있는지 봅니다.
- [ ] `웹화면_업데이트_사무실PC.bat` 더블클릭 → [1]~[4]단계 후 `Ready` 확인
  - ❗ 패키지 설치가 실패하면 `frontend_old_v0.9.0\node_modules`를 새 `frontend`에 복사한 뒤 다시 실행합니다.

## 5단계 — 화면 확인 (`http://192.168.30.201:3000`)
- [ ] 위쪽 오른쪽 **`화면 v0.10.0 · 서버 v0.10.0`** 회색 글씨 확인
- [ ] 거래처관리 → 아무 거래처 편집 → "고객 제출용 명세서 사용" 체크가 보이는지(저장하지 않고 닫아도 됨)
- [ ] 발행요청목록에서 기존 건 엑셀 다운로드가 전과 같이 되는지
- [ ] (실사용 시작 시) 농협카드에 체크 → 확정 → 고객용 편집창 → 엑셀 첫 시트 `고객 제출용` 합계 = 내부용 합계

## 문제가 생기면 (되돌리기)
| 증상 | 조치 |
|---|---|
| 2단계 마이그레이션 오류 | 화면에 나온 오류 문구를 그대로 Claude에게 전달(1단계 파일만 바뀐 상태라 옛 파일로 되돌리면 그대로 동작) |
| 3단계 후 서버가 안 켜지거나 거래처 목록 오류 | 2단계(마이그레이션)를 했는지 먼저 확인 → 그래도 안 되면 `*.bak_v0.9.0` 4개를 원래 이름으로 되돌리고 재시작 bat 실행(새로 생긴 표·칸은 옛 서버가 안 쓰므로 그대로 둬도 됨) |
| 4단계 후 화면 오류 | 화면 창 닫기 → 새 `frontend`를 `frontend_failed_v0.10.0`으로 → `frontend_old_v0.9.0`을 `frontend`로 → `웹화면_실행_사무실PC.bat` |

- **새 화면 + 옛 서버는 동작 안 함**(새 화면이 새 API를 부름) → 서버를 되돌리면 화면도 함께 되돌릴 것. 새 서버 + 옛 화면은 동작(고객 제출용 기능만 안 보임)
