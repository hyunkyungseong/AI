# 생산공정관리 대시보드 — API 규격서 (생산공정관리시스템 전달용)

> 당사 생산공정관리시스템 개발 담당자에게 전달할 연동 문서입니다.
> **이 문서는 생산공정관리시스템 연동에 필요한 내용만 추려 정리했습니다. 내부 화면(로그인, 조회, 거래명세서 관리 등) API는 포함하지 않습니다.**
> 서버 코드: `scripts/api.py` (FastAPI) | 실행: `python scripts/api.py` (포트 8000)
> 이 문서는 API가 추가될 때마다 함께 갱신합니다. (최종 갱신: 2026-07-19)

---

## 1. 연동 방식 개요

- **방향: Push** — 당사 생산공정관리시스템이 업무의뢰서 처리를 완료할 때마다, 이 서버의 API를 호출해서 데이터를 보내주는 방식입니다. (우리 쪽이 주기적으로 가지러 가는 방식이 아닙니다)
- **전송 단위: 업무의뢰서(건) 단위, 실시간** — 업무의뢰서 하나가 완료되면, 그 의뢰서에 속한 **모든 작업내역 행을 한 번에** 호출 1건으로 보내주셔야 합니다. (한 의뢰서의 행을 여러 번 나눠 보내면 금액 계산이 틀어집니다 — 3번 항목 참고)
- **현재 서버 주소:** `http://localhost:8000` (로컬 개발 중, 사무실 PC 이관 후 주소 확정 예정)
- **인증 (2026-07-19 확정):** `/운영통계자료수신`은 **`X-API-Key` 헤더**(고정 키, `db_config.py`의 `API_KEY` 값)로 인증합니다. 사람이 로그인하는 방식과는 별개입니다 — 시스템 간 연동이라 계정이 필요 없습니다.

서버·DB 연결 상태 확인용 (인증 불필요). 정상이면 아래와 같이 응답합니다.

```json
{"status": "ok", "db": "connected"}
```

## 3. `POST /운영통계자료수신`

업무의뢰서 하나에 속한 작업내역·자재사용량 데이터를 수신합니다. (운영통계자료·자재사용현황 데이터를 한 번의 호출로 함께 보내주시는 유일한 API입니다)

### ⚠️ 반드시 지켜야 할 것
- **같은 업무의뢰서번호에 속한 행은 반드시 한 번의 호출에 전부 포함**해서 보내주세요. 일부만 보내고 나중에 나머지를 따로 보내면, 청구페이지 합산 금액이 잘못 계산됩니다.
- **같은 업무의뢰서번호로 다시 호출하면, 기존에 저장된 그 의뢰서의 데이터는 전부 지워지고 새로 보낸 내용으로 완전히 교체**됩니다. (수정·정정 시 안전하게 재전송 가능)
- **인증 필수 (2026-07-19 추가):** 요청 헤더에 `X-API-Key: <전달받은 키 값>`을 반드시 포함해야 합니다. 키가 없거나 틀리면 401 오류가 반환됩니다.

### 요청 (Request Body, JSON)

```json
{
  "업무의뢰서번호": "93690",
  "운영통계": [
    {
      "마케팅담당자": "강서윤",
      "등록자": "강서윤",
      "업무명": "정기청구서",
      "작업일자": "2026-07-19 10:00:00",
      "작업내역서번호": 12345,
      "작업내역서": "거래처명 - 업무상세내용",
      "작업명": "개인일반",
      "작업내역서상세": "상세 설명 (선택)",
      "반제품여부": "N",
      "P수": "1P",
      "장수": 100,
      "건수": 50,
      "출력페이지": 100,
      "청구페이지": 100
    }
  ],
  "자재사용현황": [
    {
      "작업내역서번호": 12345,
      "작업일자": "2026-07-19",
      "자재종류": "봉투",
      "작업명": "개인일반",
      "자재명": "일반봉투 100매",
      "자재형태": "일반봉투",
      "사용량": 50
    }
  ]
}
```
> 예시에는 `자재명`·`자재형태`를 둘 다 넣었지만 실제로는 어느 한쪽만 보내주셔도 됩니다(`자재형태`가 있으면 그 값이 우선 사용되고, `자재명`만 있으면 저희 쪽에서 자동으로 분류합니다 — 아래 필드 설명·지원 안내 참고).

### 필드 설명

| 필드 | 위치 | 타입 | 필수 | 설명 |
|---|---|---|---|---|
| 업무의뢰서번호 | 최상위 | 문자열 | 필수 | 이 요청 전체가 속한 업무의뢰서번호 (숫자처럼 보여도 문자열로 보내주세요) |
| 운영통계 | 최상위 | 배열 | 필수(1개 이상) | 이 의뢰서에 속한 작업내역 행 목록 |
| 자재사용현황 | 최상위 | 배열 | 선택(없으면 `[]`) | 이 의뢰서에 관련된 자재 사용 내역 |
| 마케팅담당자 | 운영통계 행 | 문자열 | 필수 | 담당 직원명 |
| 등록자 | 운영통계 행 | 문자열 | 필수 | 실제 작업 등록자 |
| 업무명 | 운영통계 행 | 문자열 | 필수 | 업무 분류명 |
| 작업일자 | 운영통계 행 | 문자열 | 필수 | `YYYY-MM-DD HH:MM:SS` 형식 권장 |
| 작업내역서번호 | 운영통계 행 | 정수 | 필수 | 작업 내역서 고유 번호 |
| 작업내역서 | 운영통계 행 | 문자열 | 필수 | `"거래처명 - 업무상세"` 형식 (앞부분이 거래처명으로 자동 분리됨) |
| 작업명 | 운영통계 행 | 문자열 | 필수 | 작업 세부 분류 |
| 작업내역서상세 | 운영통계 행 | 문자열 | 선택 | 상세 설명 |
| 반제품여부 | 운영통계 행 | 문자열 | 선택(기본 "N") | "Y"면 건수를 0으로 처리(봉입 없음) |
| P수 | 운영통계 행 | 문자열 | 선택 | 건당 장 수 (예: "1P") |
| 장수 | 운영통계 행 | 정수 | 선택(기본 0) | 출력용지 장수 |
| 건수 | 운영통계 행 | 정수 | 선택(기본 0) | 봉입건수 |
| 출력페이지 | 운영통계 행 | 정수 | 선택(기본 0) | 장비출력페이지 |
| 청구페이지 | 운영통계 행 | 정수 | 선택(기본 0) | 실제출력페이지 |
| 작업내역서번호 | 자재 행 | 정수 | 필수 | 어느 작업내역서에 대한 자재인지 |
| 작업일자 | 자재 행 | 문자열 | 필수 | `YYYY-MM-DD` 형식 |
| 자재종류 | 자재 행 | 문자열 | 필수 | `봉투` / `용지` / `삽지` / `미구분` 중 하나 |
| 작업명 | 자재 행 | 문자열 | 선택 | 이 자재 사용이 속한 작업명(없으면 운영통계자료와 작업내역서번호로 추정 매칭 — 아래 요청 참고) |
| 자재명 | 자재 행 | 문자열 | 선택 | (2026-07-19 추가) 자재 원본 이름. `자재종류`가 `봉투`인 행에서 보내주시면 이름에 "각대"·"대봉투" 포함 여부로 자동 분류합니다 |
| 자재형태 | 자재 행 | 문자열 | 선택 | (2026-07-19 추가) 이미 분류된 값을 직접 보내고 싶은 경우(예: `일반봉투`/`각대대봉투`, 향후 `소봉투`/`중봉투`/`대봉투` 등도 가능). 정해진 값 목록이 아니라 자유 문자열이며, `자재명`보다 우선 적용됩니다 |
| 사용량 | 자재 행 | 정수 | 선택(기본 0) | 자재 사용 수량 |

> 자재사용현황 행에는 업무의뢰서번호를 따로 넣지 않습니다 — 요청 최상위의 업무의뢰서번호에 자동으로 귀속됩니다.

> **✅ 지원 안내 (2026-07-19 갱신):** `자재종류`가 `봉투`인 행에 `자재명` 또는 `자재형태`를 보내주시면 이제 저희 쪽에서 값을 그대로 받아 저장합니다(둘 다 안 보내면 지금처럼 "일반봉투"로 간주). `자재형태`는 자유 문자열이라 `일반봉투`/`각대대봉투` 외에 `소봉투`/`중봉투`/`대봉투` 같은 값을 보내주셔도 저장됩니다.
> **다만 지금은 저장까지만 지원되고, 실제 청구 단가 계산은 여전히 "일반봉투/각대대봉투" 2종 기준으로만 동작합니다.** 그 외 값을 보내주시면 저장은 정확히 되지만, 청구 금액에는 아직 반영되지 않고 "각대대봉투가 아니면 일반 단가"로 계산됩니다. 소/중/대별로 실제 단가를 다르게 매기는 기능은 저희 쪽 내부 작업이 필요해 별도로 준비 중이며, 준비되는 대로 이 문서를 다시 갱신해 안내드리겠습니다. 배치 업로드 경로는 이미 정상 처리되고 있습니다.

> **📌 요청 (2026-07-19 추가):** 자재 행에도 `작업명` 필드를 추가로 보내주시면 좋겠습니다. 하나의 작업내역서번호에 작업명이 여러 개 섞여 있는 경우(예: 같은 작업내역서로 여러 건을 함께 처리한 경우), 지금은 이 필드가 없어 저희 쪽에서 운영통계자료와 작업내역서번호로만 추정 매칭하는데, 그 작업내역서에 작업명이 여러 개 걸쳐 있으면 자재 수량이 실제보다 부풀려질 수 있습니다. 배치 업로드(`data/자재사용현황.xlsx`)에는 이미 작업명(작업이름)이 있어 그쪽은 정확히 처리됩니다.

### 응답 (성공, 200)

```json
{
  "status": "ok",
  "업무의뢰서번호": "93690",
  "운영통계_반영행수": 1,
  "자재사용현황_반영행수": 1
}
```

### 오류 응답

| 상태 코드 | 상황 | 예시 |
|---|---|---|
| 400 | `운영통계` 배열이 비어 있음 | `{"detail": "운영통계 배열이 비어 있습니다"}` |
| 422 | 필수 필드 누락·타입 오류 (FastAPI 자동 검증) | 필드별 오류 상세 반환 |
| 500 | DB 반영 실패 (서버·DB 문제) | `{"detail": "DB 반영 실패: ..."}` — 이 경우 재시도 요청 |

## 4. 참고 — 처리 과정에서 자동으로 계산되는 값

아래 값들은 보내주실 필요 없이, 서버에서 자동으로 계산해 저장합니다:
- **거래처명·업무명상세**: `작업내역서` 필드를 `" - "` 기준으로 분리해서 자동 추출
- **사업부**: `마케팅담당자` 기준으로 자동 분류
- **연월·날짜·시간대**: `작업일자` 기준으로 자동 파생
- **확정청구페이지**: 같은 업무의뢰서번호+업무명 그룹 전체를 보고 3가지 규칙 중 하나로 자동 계산 (그래서 그룹의 모든 행을 함께 보내주셔야 합니다)
- **봉투_사용량·용지_사용량·삽지_사용량·미구분_사용량**: `자재사용현황` 배열을 자재종류별로 자동 집계
