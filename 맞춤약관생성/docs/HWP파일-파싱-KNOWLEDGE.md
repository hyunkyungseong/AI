## 📌 프로젝트 개요
- **프로젝트명:** HWP파일 파싱
- **목적:**
  1. 생명보험사에서 보험상품에 대한 약관을 HWP파일로 관리하고 있음
  2. 고객이 보험상품 가입 시 특약을 가입하게 됨
  3. 가입된 특약을 발췌하여 개인별 맞춤약관을 PDF파일로 생성하려고 함
  4. 한글 원본인 HWP를 XML파일로 저장하여 파싱작업이 필요함
- **결과물 전달 대상:** 우리 팀 내부
- **팀 규모:** 나 혼자
- **주 사용자 유형:** 비개발자 (코딩을 잘 모름)

## 📖 도메인 용어 정의

| 용어 | 정의 |
|---|---|
| 보통약관 | 보험 상품 전체에 공통 적용되는 기본 약관 |
| 특별약관(특약) | 보통약관에 추가로 가입하는 선택 약관. 가입자마다 다름 |
| 맞춤약관 | 가입자가 실제 가입한 특약만 추려낸 개인화 약관 |
| 관(款) | 보통약관의 최상위 구분 단위 (예: 제1관 목적 및 용어의 정의) |
| 장(章) | 특약의 최상위 구분 단위 (예: 제1장. 상해관련 특별약관) |
| 조(條) | 관/장 아래의 세부 조문 단위 (예: 제1조(목적)) |
| 담보코드 | 개별 특약을 식별하는 코드 (예: LK501G). 맞춤약관 KEY로 사용 |
| 상품코드 | 보험 상품을 식별하는 코드 (예: L3912, L3913) |
| L00000 | 공통 담보코드. 보통약관·가이드북·제도성 특약 등 모든 가입자에게 포함되는 항목 |
| 조건표 | 상품별 담보코드·목차명·페이지 정보를 관리하는 엑셀 파일. 맞춤약관 마스터 데이터 |
| ParaShape | XML에서 단락 서식을 참조하는 ID값. XSL에서 CSS로 정의됨 |
| CharShape | XML에서 글자 서식을 참조하는 ID값. XSL에서 CSS로 정의됨 |

## 🔑 주요 결정사항
- **파일 형식**: XML + XSL 조합으로 진행 (원본 서식 유지 가능)
- **파싱 전략**: 보통약관과 특약의 구조가 달라 **별도 파싱 로직** 필요
  - 보통약관: `<P>` 단락 기준 파싱
  - 특약: `<TABLE>` 태그 안의 장·특약명 + 이후 `<P>` 조문 파싱
- **KEY 구조**: 상품코드 + 담보코드 (예: L3912 + LK501G)
  - 마스터 데이터: 엑셀 조건표 sheet2 (목차명 ↔ 담보코드 매핑)
  - `<INDEXMARK>` 태그는 19개뿐으로 전체 특약 커버 불가 → 사용 안 함
- **알고리즘 방향**: 삭제 방식
  - 원본 XML 전체 유지 후 미가입 특약만 삭제
  - 삭제 대상 = 전체 특약 − L00000(공통) − 가입자 담보코드(가입 특약)
- **텍스트 비교 방식**: P 단락 단위로 CHAR 이어붙인 후 공백 정규화 비교 (SKILL-02 참고)
  - 개별 CHAR 비교 시 `경증간편가입Ⅲ` 등 서식 분할 구간에서 부분 일치 발생
- **PDF 변환 방식**: 한컴오피스 COM 자동화 (`win32com`) 사용
  - 이유: HWPML 원본 형식을 한글이 직접 열고 저장 → 서식 100% 보존
  - weasyprint·wkhtmltopdf는 HTML 변환 과정에서 서식 손실 가능 → 불채택

## 📄 PDF 출력 고려사항

### 폰트
| 항목 | 결정 | 이유 |
|---|---|---|
| **폰트 처리 방식** | **서브셋 임베딩** | 이미지화 시 텍스트 검색 불가, 파일 크기 급증, 모바일 확대 시 흐려짐 |
| 폰트 이미지화 | 불채택 | 고객이 약관 내용을 검색·복사해야 하는 법적 문서 특성에 부적합 |
| 한컴 COM 저장 | 서브셋 임베딩 자동 적용 | 별도 처리 불필요 |

### 파일 크기
- 모바일 발송(카카오톡 등) 기준 **5MB 이하** 권장
- 텍스트+표 위주 약관은 1~3MB 수준 예상
- 이미지(별표 등) 포함 시 JPEG 압축 적용 검토

### 보안 설정
| 항목 | 설정 |
|---|---|
| 인쇄 | 허용 (출력 목적) |
| 텍스트 복사 | 정책에 따라 결정 |
| 편집·수정 | **금지** (법적 문서) |
| 암호화 | 고객 개인정보 포함 시 검토 |

### PDF 표준
- 일반 배포: **PDF 1.4~1.7** (모바일·PC 호환성 최고)
- 법적 장기 보관: **PDF/A** 검토 (폰트 완전 임베딩 강제)

### 레이아웃
- 용지 크기: **A4** (원본 HWP와 동일)
- 페이지 방향: 세로(Portrait) 유지
- 텍스트 레이어 포함 필수 → 검색·복사 가능
