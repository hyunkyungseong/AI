# 거래명세서 Excel — 구분/규격/비고 조건식 입력 + 담당자 연락처 자동화

> 상태: ✅ 완료(2026-08-12) — 로컬 PC 구현·검증·사용자 실제 화면 확인(KB증권 거래원장)까지 전부 끝남 + **사무실 PC 배포까지 완료(2026-08-12)**. 후속 개선 이력은 맨 아래 "후속 작업" 절 참고.

## Context (왜 필요한가)

사용자가 실제 발행된 거래명세서 Excel 스크린샷을 보여주며 두 가지를 요청:

1. 지금 청구품목규칙(조건식) 화면에서는 "최종청구품명"만 입력 가능한데, **"구분"·"규격"·"비고"** 칸도 규칙 단위로 사용자가 직접 입력해서 Excel에 표기하고 싶음(스크린샷 예: 규격="A4"/"230*110", 비고="추가내역서 봉입"/"2월-4월 반송처리비").
2. 문서 하단 좌측의 "담당자 : 노재민팀장(010-9700-0055) / jaemin.noh@dshw.co.kr"가 **지금 고정 텍스트**로 박혀있는데, 거래처+업무명별로 당사 담당자(이름·전화·이메일)를 등록해두면 자동으로 표기되게 하고 싶음. 사용자 확정 설계: **"담당자가 먼저 있고, 그 담당자 밑에 여러 거래처+업무명을 등록"**하는 구조 — 담당자가 바뀌면(퇴사 등) 담당자 레코드 하나만 수정해도 연결된 모든 거래처에 자동 반영되어야 함(거래처마다 일일이 들어가서 고치는 방식 금지).

## 핵심 조사 결과 (템플릿 직접 열어 확인 완료)

`data/거래명세서_템플릿_base.xlsx`(2번째 시트)를 openpyxl로 직접 읽어 확인:

- **15행 헤더에 이미 `H15="규 격"`, `N15="비 고"` 컬럼이 존재**하고, 품목 행(16~29행, `A/D/I/J/K`열만 코드가 채움)의 H열·N열은 지금 코드가 전혀 안 씀 → 그대로 재사용 가능(신규 셀 추가 불필요).
- 품목 행마다 `B{r}:C{r}` 병합이 행별로 따로 있어(현재는 첫 행에만 발행일 자동 기입, 나머지는 공백), **행별로 다른 "구분" 텍스트를 넣는 것도 템플릿 구조상 문제없음**.
- 소계 행(`N{소계_행}`, 기본 30행)은 부가세 금액 표시용으로 이미 재활용 중(`scripts/billing.py:458-466`) — 품목 행(16~29) 범위와 겹치지 않으므로 안전.
- **담당자 연락처는 `B31` 셀 하나**에 `"  담당자 : 노재민팀장(010-9700-0055)\n               jaemin.noh@dshw.co.kr"` 형태(줄바꿈 포함 단일 문자열)로 템플릿에 고정 저장. `scripts/billing.py`가 이 셀을 전혀 안 건드림.
- 품목 행이 14개(16~29행)를 넘으면 `_insert_extra_item_rows()`가 20행을 복제해 동적으로 행을 늘림(병합·인쇄영역·dimension까지 함께 조정) — 규격·비고 주입은 `for i, row in enumerate(품목행목록): r = 16+i` 반복문 안에서 이뤄지므로 가변 행 삽입과 무관하게 정상 동작(2026-08-11 사용자 재확인).

**⚠️ 이름 충돌 주의:** `거래명세서_품목` 테이블에는 이미 `구분 ENUM('원본','최종')`(원본/최종 스냅샷 구분용) 컬럼이 존재함. 신규 "구분"(Excel B열 표시용 텍스트)을 이 테이블에 **같은 이름으로 추가하면 안 됨** — 컬럼명 충돌. 전 구간(DB 컬럼명·Pydantic·TS 타입·billing.py dict 키)에서 신규 필드명은 **`구분표시`**로 통일(화면 라벨은 그대로 "구분"으로 보여줘도 무방, 내부 식별자만 구분).

기존 "조" 컬럼 추가 시(2026-07-29~08-01) 정확히 같은 패턴(`청구품목규칙`·`청구품목통합규칙`·`거래명세서_품목` 3개 테이블에 나란히 컬럼 추가 + `scripts/api.py`의 규칙조회/저장/미리보기/확정저장/재다운로드 각 지점 반영)을 이미 밟은 전례가 있어, 이번 것도 그 패턴을 그대로 복제하면 됨(`scripts/init_db_mariadb.py`의 `migrate()` 함수, 306~328행 참고).

담당자 정보를 저장할 기존 테이블 없음(`사용자` 테이블은 로그인 전용, 전화·이메일 컬럼 없음 / `거래처마스터.수신이메일`은 고객사 수신처용) — **신규 테이블 필요**.

## 설계 B — 담당자 연락처 자동화 ("담당자 우선" 구조, 사용자 확정)

**DB 신규 테이블 2개** (`scripts/init_db_mariadb.py`):
```sql
CREATE TABLE IF NOT EXISTS 담당자 (
    id        INT AUTO_INCREMENT PRIMARY KEY,
    이름      VARCHAR(50) NOT NULL,
    전화번호  VARCHAR(30),
    이메일    VARCHAR(100),
    등록일    DATETIME DEFAULT CURRENT_TIMESTAMP,
    수정일    DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ...;

CREATE TABLE IF NOT EXISTS 담당자_담당거래처 (
    id        INT AUTO_INCREMENT PRIMARY KEY,
    담당자_id INT NOT NULL,
    거래처명  VARCHAR(100) NOT NULL,
    업무명    VARCHAR(200),           -- NULL = 그 거래처 전체 기본(단가마스터와 동일 관례)
    등록일    DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (담당자_id) REFERENCES 담당자(id) ON DELETE CASCADE,
    UNIQUE KEY uk_거래처업무 (거래처명, 업무명)
) ...;
```
조회는 "거래처명+업무명 정확일치" → 없으면 "거래처명 + 업무명 NULL(거래처 기본)" 순서로 폴백(`단가마스터`의 3단계 폴백과 같은 관례). 담당자 삭제 시 매핑도 함께 삭제(CASCADE).

**프론트:** `frontend/components/ClientMasterSection.tsx`의 하위 탭 배열(17~18행, 현재 `clients`/`pricing`)에 `{ id: "staff", label: "담당자관리" }` 추가. 신규 `StaffMaster.tsx`(가칭) — 담당자 목록(이름/전화/이메일) CRUD + 담당자 1명을 선택하면 그 담당자가 맡은 "거래처+업무명(업무명 비우면 전체 기본)" 목록을 추가/삭제하는 하위 UI. 담당자 정보(이름/전화/이메일) 수정은 이 화면 한 곳에서만 하면 연결된 모든 거래처에 자동 반영됨.

**백엔드(`scripts/api.py`):** 담당자 CRUD 엔드포인트 신규(거래처마스터 CRUD와 동일 패턴) — 담당자 등록/수정/삭제, 담당자별 거래처+업무명 매핑 추가/삭제.

**`scripts/billing.py`:**
- 신규 `_담당자_조회(cur, 거래처명, 업무명)` — 위 2단계 폴백으로 담당자 dict(`{"이름","전화번호","이메일"}`) 또는 `None` 반환.
- `write_거래명세서_excel()`에 담당자 dict를 추가 인자로 받아, 있으면 `B31` 텍스트를 `f"  담당자 : {이름}({전화번호})\n               {이메일}"`(기존 포맷·들여쓰기 그대로)로 동적 교체하는 `_set_str` 호출 추가. **없으면 아무것도 안 하고 템플릿 고정 텍스트 그대로 노출**(담당자 미등록 거래처는 지금과 완전히 동일하게 보임 — 안전한 기본값, 점진 도입 가능).

1. **미리보기 화면 가독성 개선** — 오른쪽 표에 구분·규격·비고 컬럼 3개가 추가되며 가로 스크롤 발생 → 표에서는 빼고 조건식 편집창에서만 입력하도록 되돌림 + 좌우 표 비율 40:60 조정(오른쪽에 더 넓게) + 표 컬럼 패딩 확대 + 조건식 편집창 폭 확대(`max-w-md`→`max-w-xl`)
2. **"새 행 추가" 품명 자동완성 1차** — `GET /거래명세서품명이력?거래처명=X` 신규(당시엔 전체 이력), 수동 입력 품명을 다음에 다시 쓸 때 자동완성 후보로 제시
3. **품명 이력이 거래명세서 취소 시 사라지는 버그 수정 + 체크박스 다중 추가 UI** — 원인: `거래명세서_품목`이 거래명세서 취소(DELETE) 시 FK CASCADE로 함께 삭제되어 이력도 같이 사라짐 → **별도 영속 테이블 `거래명세서품명이력` 신설**(취소 API가 손대지 않음, 확정 시에만 upsert). UI는 체크박스로 여러 개 골라 "선택 추가"하는 방식으로 일단 구현
4. **"전월 기준 자동 반영"으로 1차 재설계** — 체크박스 선택 UX 자체를 없애고, 전월(직전 캘린더월)에 새 행으로 썼던 품명을 미리보기 오픈 시 선택 없이 곧바로 표에 행으로 자동 추가하도록 변경. 조건식(규칙) 품명이 이력에 섞이지 않도록 `수동입력` 플래그(프론트가 각 확정 행에 `조건===null` 여부를 실어 보냄, 서버는 `수동입력=true`인 것만 이력 테이블에 저장)도 이때 추가
5. **"가장 최근 확정분 기준"으로 최종 재확정** — "전월(달력 기준)"은 취소 시점이 항상 지난달인 게 아니라는 사용자 지적으로, `GET /거래명세서품명이력`을 **그 거래처의 가장 최근 확정(취소돼도 무관)에 쓰인 품명만** 반환하도록 변경(`등록일 = (SELECT MAX(등록일) ...)` 서브쿼리). 확정할 때마다 그 확정에 쓰인 품명들의 등록일이 함께 갱신되므로, 같은 확정끼리는 같은 등록일을 공유한다는 성질을 이용 — DB 스키마 변경 없이 쿼리만 수정
