## Context (왜 이 작업을 하는가)

당사 생산공정관리시스템이 5월분 `운영통계자료`부터 새 컬럼 10개(`압착·주소출력·봉입·수작업·중철·제본·무광코팅·유광코팅·에폭시·날개접지`)를 내려주기 시작했다. `data/7월운영통계자료.xlsx`(5월분 8,438행) 실데이터 분석 + 사용자 확인으로 다음이 확정됐다:

1. 5개(압착/봉입/수작업/중철/제본)는 "합산"이 아니라 "OR-flag(그 공정을 거친 물량이 해당 컬럼에 건수와 동일한 값으로 반복 표시)" 방식 — 실사례: 의뢰서 96373 "맞춤형약관 출력"(건수=12, 수작업=12, 제본=12, 합산 아님 → 제본 후 수작업 인입), 96299 "계약보전 웰컴팩"(건수=515, 중철=515, 수작업=515 → 중철물 수작업 인입).
2. **사용자 확정 요구사항**: 고객사 거래명세서 발행 시 압착비·봉입(기계봉입)비·수작업비·중철비·제본비를 **각각 별도 항목으로 청구**해야 하고, 나머지 4개(주소출력·무광코팅·유광코팅·에폭시·날개접지)도 청구 대상에 포함해야 한다(9개 신규 필드 전부).
3. **기존 필드 재사용**: `단가마스터.봉입단가`("봉입"용) / `단가마스터.각대대봉투봉입단가`(UI 라벨 "수작업 단가" — `scripts/app.py` 1134·1160·1246행, "수작업"용)를 그대로 재사용. `.claude/plans/bug_각대대봉투_봉입비_계산.md`(2026-07-22)가 "개별 작업 건 단위 봉투형태(기계/수작업) 데이터가 들어오면 봉입비를 두 항목으로 분리하라"고 예견해둔 바로 그 시점. 나머지 8개(압착·주소출력·중철·제본·무광코팅·유광코팅·에폭시·날개접지)는 대응 필드가 없어 신규 저장 방식 필요.
4. **청구서 인쇄 코드**(`data/거래명세서_템플릿_base.xlsx` sharedStrings 확인 완료): `P(출력)/M(기계)/E(봉투)/F(용지)/H(수작업)/BB(중철,제본)/AB(부가사업)/D(디자인)` 범례가 이미 인쇄돼 있고 `billing.py` `코드표순서`에도 H/BB/AB가 이미 예약돼 있었음 —
   - 수작업비 → `H`
   - 중철비·제본비 → `BB`(범례에 이미 "중철,제본" 명시 — 봉입비·삽지비가 `M`을 공유하는 것과 동일 방식, 가격은 각자 별도 계산)
   - 압착비·주소출력비·무광코팅비·유광코팅비·에폭시가공비·날개접지비(6개) → `AB`(부가사업) 통합 인쇄(사용자 확정, 2026-08-21)
5. **미분류 케이스 전부 설명됨**(사용자 확인): 학원교재류(대성학원·보이드·파피, 83건)는 "커팅" 공정(이번 대상 아님) 후 학원 납품이라 출력공정만 청구. 채권양도통지서 내용증명은 전산자료처리 업무. 둘 다 이번 기능과 무관, 코드 변경 없음.
