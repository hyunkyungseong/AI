## 📌 프로젝트 개요
- **프로젝트명:** 작업현황 대시보드 생성
- **업종:** DM(다이렉트메일) 및 교재 제작
- **목적:**
  1. 공정관리시스템 자료(`운영통계자료.xlsx`)를 활용해 통계 생성
  2. 거래처별 출력·봉입 작업 현황을 시각화
  3. 생산 작업에 대한 거래명세서 발행 관리
  4. 거래명세서 미발행 건 존재 여부 체크
  5. 웹 환경에서 대시보드를 팀 내부에서 볼 수 있게 함
- **주요 시각화 항목:**
  - 거래처별 작업 현황 (출력, 봉입)
  - 전월 대비 현황
  - 전년 동월 대비 현황
  - 담당자별 작업 현황
  - 거래명세서 발행 현황 및 미발행 건 알림
- **원본 데이터:** `data/운영통계자료.xlsx`
- **결과물 전달 대상:** 우리 팀 내부
- **팀 규모:** 2 ~ 5명
- **주 사용자 유형:** 비개발자 (코딩을 잘 모름)

## 🔄 핵심 업무 흐름

```
[운영통계자료.xlsx 업데이트]
         ↓
[데이터갱신_후_실행.bat 실행 → preprocess.py 자동 처리]
         ↓
[대시보드에서 작업 현황 확인]
         ↓
[마케팅 담당자: 미발행 목록에서 의뢰서 선택]
  → 📋 복사 버튼으로 의뢰서번호 복사 (파이프 구분, 예: 94361|94362)
  → Excel 세금계산서 "요청사항" 시트에 붙여넣기 (향후 추가 예정)
  → "거래명세서 요청" 버튼 클릭
         ↓
[거래명세서이력 DB에 발행대기(발행여부=0) 저장 → 미발행 목록에서 즉시 제거]
         ↓
[경영지원부 담당자: 발행요청목록에서 검색]
  → Excel "요청사항" 시트에서 의뢰서번호 복사 (파이프 구분)
  → 발행요청목록 상단 검색창에 붙여넣기 → "검색" 버튼 클릭
  → 합계(장수·봉입건수·출력페이지·청구페이지) 확인
         ↓
[이상 없으면 "거래명세서 발행" 버튼 클릭 → 발행완료(발행여부=1) 업데이트]
         ↓
[거래명세서 Excel 생성 → 고객사에 이메일 발송 (미구현)]
```

- **미발행 건:** 거래명세서이력 DB에 등록되지 않은 업무의뢰서 (발행여부 관계없이 이력에 있으면 미발행 목록에서 제외)
- **발행여부 값:** `0` = 발행대기 (마케팅 요청됨), `1` = 발행완료 (경영지원부 처리됨)
- **담당자 역할 분리:** 마케팅 담당자(요청) ↔ 경영지원부 담당자(검토·발행)
- **의뢰서번호 전달 형식:** 파이프(`|`) 구분 한 줄 문자열 (복사 버튼 생성 형식과 동일)

## 🚀 최종 배포 목표

> ⚠️ **현재 단계:** 로컬 개발 완료 (SQLite + 로컬 Streamlit)
> **다음 단계:** 원격 PC에 Streamlit 배포 → 팀 전체 사용 (DB는 SQLite 파일 공유 방식 유지)
> **보류:** MariaDB 전환은 후순위로 미룸 (필요 시 별도 검토)

### 목표 아키텍처
```
[현재 — 로컬 개발]
  로컬 PC
  ├── 운영통계자료.xlsx → preprocess.py → processed.pkl
  ├── SQLite (work/dashboard.db)
  └── Streamlit → http://localhost:8501

[목표 — 원격 배포]
  원격 서버 PC
  ├── SQLite (work/dashboard.db) — 파일 그대로 유지
  ├── 운영통계자료.xlsx → preprocess.py → processed.pkl
  └── Streamlit 서버 → 팀원 브라우저 접속 (http://[서버IP]:8501)

[보류 — MariaDB 전환]
  원격 서버 PC
  ├── MariaDB DB (거래처마스터·단가마스터·거래명세서이력·운영통계 테이블)
  └── Streamlit (pymysql 드라이버로 교체 필요)
```

### 접속 방법 (배포 후)
| 방법 | 접속 주소 예시 | 특징 |
|---|---|---|
| IP 직접 접속 | `http://192.168.x.x:8501` | 설정 불필요, 가장 간단 |
| hosts 파일 설정 | `http://dashboard.company.local:8501` | 팀원 PC hosts 파일 1줄 추가 |
| nginx 리버스 프록시 | `http://dashboard.company.local` | 포트 없이 접속 (nginx 설치 필요) |

> 팀 규모(2~5명) 사내 사용 기준 → **hosts 파일 방법 권장**

### 전환 작업 순서
> CHANGELOG.md ⏭ 섹션에 단계별 상세 항목 기재

1. 원격 PC: MariaDB + HeidiSQL 설치, DB·계정·방화벽(3306·8501 포트) 설정
2. 현재 PC: `db_config.py`·`init_db_mariadb.py`·`migrate_sqlite_to_mariadb.py` 신규 작성
3. 현재 PC: `preprocess.py` 수정 (pkl → MariaDB INSERT), `app.py` 수정 (pymysql 전환)
4. 원격 PC: Python + 패키지 설치, 파일 복사, DB 적재·검증, Streamlit 배포

### 핵심 계산 로직 (출력 vs 봉입)

> **출력과 봉입은 별도 행이 아니라 같은 행에 함께 기록됩니다.**

| 지표 | 사용 컬럼 | 설명 |
|---|---|---|
| 출력량 (장비 기준) | `출력페이지` (장비출력페이지) | 장비가 처리한 페이지 수. 양면 뒷면 미인쇄도 포함 |
| 출력량 (실제 기준) | `청구페이지` (실제출력페이지) | 실제 인쇄된 페이지만 집계 |
| 종이 소비량 | `장수` (출력용지 장수) | 사용된 종이 장 수 |
| 봉입량 | `건수` (봉입건수) | 봉투에 넣은 건 수 |

**과금(거래명세서) 기준:**
- 거래처별로 다름: `출력페이지` 기준 또는 `청구페이지` 기준
- 카드사 등 대형 거래처는 `청구페이지`(실제출력페이지) 기준으로 거래명세서 발행

**업무의뢰서번호 단위 청구 계산 규칙:**
```
[경우 1] 첫 행만 청구페이지 > 0, 나머지 행은 모두 0
  Row 1: 청구페이지 = 500  ← 전체 합계가 이미 첫 행에 표기됨
  Row 2: 청구페이지 = 0
  Row 3: 청구페이지 = 0
  → 청구 = 500 (첫 행 값 그대로 사용)

[경우 2] 2번째 이후 행 중 청구페이지 > 0 인 행이 하나라도 존재
  Row 1: 청구페이지 = 200
  Row 2: 청구페이지 = 150
  Row 3: 청구페이지 = 0
  → 청구 = 200 + 150 + 0 = 350 (첫 행부터 마지막 행까지 합산)

[경우 3] 그룹 내 모든 행의 청구페이지 = 0
  Row 1: 청구페이지 = 0, 출력페이지 = 200
  Row 2: 청구페이지 = 0, 출력페이지 = 100
  → 청구 = 200 + 100 = 300 (전체 행의 출력페이지 합산)
```

## 🔑 주요 결정사항

- **반제품 처리 (2026-06-07 확정):** 반제품여부=Y인 행은 봉입 작업이 없으므로 해당 행의 건수를 0으로 처리. preprocess.py `apply_반제품_logic()`에서 청구페이지 계산 전에 자동 적용.
- **출력/봉입 집계 방법:** 출력과 봉입은 같은 행에 함께 기록됨. `건수`=봉입건수, `출력페이지`=장비출력페이지, `청구페이지`=실제출력페이지로 각각 집계
- **청구 단위:** `업무의뢰서번호` 기준으로 청구페이지를 계산. 단, 거래명세서 발행 시 여러 업무의뢰서번호를 합쳐서 1장으로 발행하는 경우도 있음
- **청구페이지 계산 규칙 (업무의뢰서번호 그룹 기준):**
  - 경우 1 — 첫 행만 청구페이지 > 0, 나머지 모두 0 : 첫 행의 청구페이지 그대로 사용 (전체 합계가 이미 표기된 것)
  - 경우 2 — 2번째 이후 행 중 청구페이지 > 0 존재 : 첫 행부터 마지막 행까지 청구페이지 합산
  - 경우 3 — 그룹 내 모든 행 청구페이지 = 0 : 전체 행의 출력페이지 합산으로 청구
- **과금 기준:** 거래처별로 다름. 카드사 등 대형사는 `청구페이지` 기준으로 거래명세서 발행
- **공급가액 계산 공식 (확정):**
  ```
  봉입건수    = 업무의뢰서번호 그룹 내 전체 건수 합계
  추가용지    = 장수_합 - 봉입건수_합  (장수 또는 봉입건수가 0이면 0)
  출력료      = 확정청구페이지 × 출력단가
  봉입료      = 봉입건수 합계  × 봉입단가
  추가봉입비  = (삽지_사용량_합 + 추가용지) × 추가봉입단가
  용지제작비  = 용지_사용량_합 × 용지제작단가
  봉투제작비  = 봉투_사용량_합 × 봉투제작단가
  삽지제작비  = 삽지_사용량_합 × 삽지제작단가
  공급가액    = 출력료 + 봉입료 + 추가봉입비 + 용지제작비 + 봉투제작비 + 삽지제작비
  세액        = 공급가액 × 10%
  합계        = 공급가액 + 세액
  ```
  - 추가용지 = 봉투 없이 용지만 투입된 수량 (장수 - 봉입건수)
  - 단가 필드가 DB에서 null인 경우 0으로 처리 (NaN 연산 버그 방지)
  - 모든 단가는 거래처·업무명·작업명 조합별로 상이 → 단가마스터 fallback 조회
  - (업무의뢰서번호, 작업명) 단위로 단가 각각 적용 후 합산 (2026-06-21 완료)
- **거래처마스터 테이블 (SQLite):** 거래처 기본정보만 관리 (단가 제외, 2026-06-21 변경)
  ```
  거래처명(PK), 사업자등록번호, 수신이메일, 비고, 등록일, 수정일
  ```
- **단가마스터 테이블 (SQLite, 2026-06-21 신규):** 거래처별 업무명·작업명 단위 단가 관리
  ```
  id(PK), 거래처명, 업무명(NULL=거래처 전체 기본), 작업명(NULL=업무명 단위 기본),
  출력단가, 봉입단가, 추가봉입단가, 용지제작단가, 봉투제작단가, 삽지제작단가, 비고, 등록일, 수정일
  UNIQUE(거래처명, 업무명, 작업명)
  ```
  단가 조회 fallback 순서:
  1. 거래처명 + 업무명 + 작업명 (가장 구체적인 예외단가)
  2. 거래처명 + 업무명 + 작업명=NULL (업무명 단위 기본단가)
  3. 거래처명 + 업무명=NULL + 작업명=NULL (거래처 전체 기본단가)
  4. 없으면 → 예상공급가액 빈 칸 표시
  운영통계자료 매핑: `작업명` 컬럼 = 단가마스터의 `작업명` (업무명상세 아님)
- **거래명세서 발행 상태 (SQLite):** 업무의뢰서번호 기준 발송 여부, 발송일, 파일 경로 저장
- **거래명세서 표준화:** 현재 거래처별로 양식이 약간씩 다름 → 표준 Excel 템플릿으로 통일 예정
- **업무의뢰서 세부항목 조회:** 대시보드에서 업무의뢰서번호 단위로 그루핑된 세부 작업 항목 (P수, 건수, 출력페이지 등) 드릴다운 조회 기능 제공
- **거래명세서 멀티 선택 발행:** 여러 업무의뢰서번호를 체크박스로 동시 선택 → 1장의 거래명세서로 합산 생성 가능. 선택 시 합계(확정청구페이지, 봉입건수, 예상공급가액) 실시간 표시
- **거래처 추출 기준:** `작업내역서` 컬럼에서 " - " 앞부분을 거래처명으로 사용
- **월별 집계 기준:** `작업일자` 컬럼의 날짜 (datetime → date 변환 필요)
