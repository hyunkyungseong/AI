# 버그: 신규 조건식 규칙 생성과 동시에 확정 시 수정이력에서 품목 수량 변경이 누락됨

> 상태: ✅ 전체 완료(2026-08-31) — 코드 수정·데이터 기반 검증·브라우저 재현 확인 + 사무실 PC 배포
> 및 사용자 확인까지 전부 완료. 로컬·사무실 PC 코드 동기화 상태, 남은 미배포 항목 없음.

## 제보 내용

D-202608-00133(KB증권, 골드&와이즈 책자 발송) — 사용자가 미리보기 화면에서 "출력비" 품목을
"라벨지출력"으로 조건식(청구품목규칙) 새로 만들면서 동시에 수량을 130 → 906으로 직접 고쳐서
확정. "원본 vs 최종 비교" 팝업의 "수정이력(3건)"에는 공급가액·부가세·합계 변경만 남고,
정작 수량이 바뀌었다는 사실 자체는 기록되지 않음.

## 원인

`scripts/api.py`의 `POST /거래명세서요청`에서 감사이력 기준선(`기준목록`)을 계산할 때, 이번
확정에서 사용자가 **방금 새로 만든 규칙**(`요청.규칙`)이 아니라 **이번 확정 이전에 DB에
저장돼 있던** 규칙(`_통합조건식_판정()`이 조회하는 `규칙목록`)만 봤음.

- KB증권+"골드&와이즈 책자 발송" 조합은 이번이 **최초로 규칙을 만드는 순간**이었으므로,
  확정 이전 DB의 `규칙목록`은 비어 있었음(청구품목규칙 id 765·766의 등록일이 이 거래명세서의
  등록일과 정확히 같은 초 단위로 일치 — 같은 트랜잭션에서 함께 생성됨을 확인).
- `규칙목록`이 비어 있으면 `기준목록`이 원본목록(가공 전, 품명 "출력비(골드&와이즈 책자 발송)")
  으로 폴백됨 — 그런데 실제 최종목록은 방금 만든 새 규칙이 적용된 "라벨지출력"이라, 이름이
  달라 (코드,품명) 키 매칭이 실패해버림.
- 2026-08-17에 이미 한 번 발견됐던 "신규 규칙 생성 + 즉시 확정 시 품목삭제+품목추가 스푸리어스
  기록" 문제를 막으려고 그때 넣어둔 guard(`if 기준_대비_변경 and 규칙목록`)가, 이런 상황을 통째로
  걸러버림 — 그 안에 섞여 있던 **진짜** 수량 변경(130→906)까지 함께 사라진 것.
- 부수 영향: 2026-08-18에 도입된 "원본 vs 최종 비교" 팝업의 왼쪽 "원본" 칸도 같은 `기준목록`
  변수를 그대로 저장(`거래명세서_품목` 구분='기준')하므로, 이 팝업의 왼쪽 칸도 새 규칙이 적용
  안 된 옛 품명("출력비(골드&와이즈 책자 발송)")으로 표시되고 있었음(같은 근본 원인, 별도 증상).

## 수정 내용 (`scripts/api.py`)

1. `기준목록` 계산 시 DB의 스테일한 `규칙목록` 대신, 이번 요청에 실려온 `요청.규칙`(프론트가 매
   확정마다 오른쪽 표의 조건식 있는 행 전체를 보내므로 사실상 항상 채워짐 — `_규칙_저장`/
   `_통합규칙_저장`이 항상 "전체 교체" 방식이라 이번 확정 후 DB에 실제로 남을 규칙과 동일)를
   우선하는 `효과_규칙목록`을 신규 도입 — `요청.규칙`이 없으면(향후 다른 API 호출자 대비 방어적
   폴백) 기존처럼 DB `규칙목록`을 씀.
2. `품목이력_항목` 계산 guard도 `규칙목록` → `효과_규칙목록` 기준으로 교체 — 기준목록 자체가
   이제 항상 올바르게 계산되므로, 신규 규칙 케이스에서도 guard가 정상적으로 통과됨.

## 검증

- `python -m py_compile scripts/api.py` 통과.
- **실제 DB 데이터(D-202608-00133) 기반 재현 검증**: 저장된 원본 품목(구분='원본')과 실제 저장된
  규칙(id 765·766)으로 수정된 로직을 그대로 재현 — `_품목_변경_이력()` 결과가 스푸리어스한
  품목삭제/추가 없이 정확히
  `{"필드명": "수량", "이전값": 130.0, "이후값": 906.0, "비고": "라벨지출력"}`
  `{"필드명": "금액", "이전값": 5200.0, "이후값": 36240.0, "비고": "라벨지출력"}`
  두 건만 남는 것을 확인(H코드 "수작업봉입비"는 수량 변경이 없었으므로 이력에 안 잡히는 것도 정상).
- **브라우저 실사용 재현 확인 완료(사용자, 2026-08-31)**: 테스트를 위해 KB증권 + "골드&와이즈
  책자 발송"의 개별조건식 2건(라벨지출력·수작업봉입비, id 767·768)을 요청에 따라 삭제해 "조건식이
  하나도 없는 최초 상태"를 재현한 뒤, 조건식을 새로 만들면서 수량을 동시에 수정 → 확정 →
  수정이력에 정상적으로 기록되는 것을 사용자가 직접 확인.

## 과거 건 처리

D-202608-00133 자체의 수정이력(공급가액·부가세·합계 3건만 남은 상태)은 **소급 정정하지 않음**
(사용자 확정, 2026-08-31) — 과거 확정건의 감사이력을 사후 조작하는 것은 위험 부담이 더 크고,
수량 130→906 변경 자체는 공급가액·부가세·합계 변동으로 이미 간접적으로 남아있음. 이번 수정은
**이후 확정되는 건부터** 적용됨.
