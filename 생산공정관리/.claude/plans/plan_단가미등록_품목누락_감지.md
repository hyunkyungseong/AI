# 단가 미등록으로 품목이 조용히 누락되는 문제 — 감지·안내 기능

> 상태: ✅ 완료(로컬 코드·검증 2026-08-22, 사무실 PC 배포 2026-08-23 — 사용자 확인, 순조롭게 완료)

## Context — 왜 이 작업을 하는가

방금 완료한 "인쇄면/청구단위" 기능을 화면에서 테스트하던 중, 사용자가 미리보기 화면(왼쪽 "시스템
자동계산 원본" 표)을 보고 지적한 문제: **이 표는 단가가 등록된 품목만 보여준다.** 즉 어떤 작업에
실제 생산 실적(장수·자재사용량·압착/제본 등 공정 수량)이 있어도, 그 항목에 대응하는 단가(기본단가든
자재별 단가든)가 하나도 등록돼 있지 않으면 그 줄 자체가 원본 표에서 아예 생기지 않는다 — 사용자
입장에서는 "그 항목은 원래 없었다"처럼 보이지만 실제로는 "계산됐는데 단가가 없어서 조용히 버려진
금액"이다.

이건 2026-08-17에 이미 한 번 발견해서 고친 **"미분류 항목" 문제**(조건식에 안 걸린 원본 항목이
있어도 확정이 막히지 않던 버그, `bug_미분류_확정시_차단없음.md`, 실제 96,960원 누락 사례로 발견)와
성격이 같다 — 실제로 청구해야 할 금액이 사용자 눈에 안 띄게 청구서에서 빠지는 것. 다만 원인이 다르다:
미분류는 "원본 표에는 있는데 오른쪽 최종 표로 안 옮겨진" 경우였고, 이번은 "원본 표 자체에 애초에
줄이 안 생기는" 경우라 기존 미분류 감지로는 못 잡는다.

## 코드에서 확인한 사실 (Read-only 조사 완료)

`scripts/billing.py`의 계산 함수들은 전부 **"단가 > 0 이고 수량 > 0"일 때만** `행데이터`에 줄을
추가하는 구조다 — 이 게이트를 통과 못하면 그 수량은 어디에도 기록되지 않고 사라진다:

- `_작업별_품목누적()`의 `항목계산` 딕셔너리 루프(추가봉입비·동봉물삽입비·수작업비·압착비·주소출력비·
  중철비·제본비·무광코팅비·유광코팅비·에폭시가공비·날개접지비) — `if 단가 > 0 and 수량 > 0:`
- `_자재별_처리()`(출력비·출력자재비·봉입비·봉입자재비·삽지비 공용) — 자재별 매칭 단가도, 못 매칭된
  잔여의 기본단가도 각각 `if 단가 > 0 ...`/`if 기본단가 > 0 and 잔여 > 0:` 게이트를 가짐
- `_자재비례배분_처리()`(청구페이지 있는 출력비) — 위와 동일한 구조
- 출력비 마지막 폴백 분기(`elif rates.get("출력단가", 0) > 0 and 청구페이지 > 0:`) — 애초에
  `출력단가 > 0`이 조건문에 들어가 있어, 0이면 그 `elif` 자체가 안 열려 아무 것도 안 남음

기존에 이미 있는 비슷한 안내 장치 `자재수량_불일치_목록()`(billing.py:455)은 "장수 vs 용지
자재사용량이 서로 다른 경우"만 잡아주는 별도 함수라 이번 문제(단가 미등록)는 감지 대상이 아니다 —
다만 이 함수가 좋은 선례다: **계산 로직 자체는 안 건드리고, 화면 안내 전용의 별도 함수**로
분리돼 있어 기존 8곳 넘는 호출부에 회귀 위험이 없다.

## 설계 방향 — 구현하며 더 단순한 방식으로 다듬음

**실제 구현은 계획의 2번(별도 `단가미등록_목록()` 함수 신설)을 쓰지 않고 더 단순하게 처리** —
`build_품목행()`이 이미 (작업명,거래처명,업무명) 단위로 원본 데이터를 모아 `_작업별_품목누적()`을
호출하는 바로 그 루프를 갖고 있어서, 그 루프를 통째로 다시 구현하는 대신 `build_품목행()` 자체에
`미등록수집=None` 선택 인자를 추가해 내부 호출에 그대로 전달하는 방식으로 바꿨다 — 같은 집계 로직이
두 곳에 따로 존재하는 것을 피함(SKILL-42와 같은 종류의 함정 회피). `/거래명세서미리보기`가 이미
`build_품목행()`을 호출하고 있으므로 별도 함수 호출·별도 순회 자체가 필요 없어짐.

- [x] `_작업별_품목누적()`·`_자재별_처리()`·`_자재비례배분_처리()`에 선택 인자 `미등록수집=None`
      (리스트) 추가 — 안 넘기면(기존 호출부 전부) 지금과 100% 동일하게 동작(회귀 없음). 넘기면,

## 확정 — 화면에 어떻게 보여줄지 (사용자 확인 완료)

**"미분류"와 동일한 확정 차단 + 경고창 방식으로 결정.** ("무광코팅 작업 자체가 없으면 경고가
뜨면 안 된다"는 요구사항은 감지 조건이 애초에 "수량>0인데 단가 없음"이라 자동으로 충족됨 —
수량이 0인 품목은 대상이 아님.)

`InvoicePreviewDialog.tsx`의 기존 미분류 확정 흐름(761~767행 `handleConfirmClick()`,
1215~1232행 `ConfirmDialog`)과 완전히 같은 패턴으로 하나 더 추가:

- 신규 state `단가미등록확인대기` 추가
- `handleConfirmClick()`을 체인으로 확장 — **단가미등록 체크를 먼저**, 통과하면 기존 미분류 체크,
  둘 다 통과해야 `applyConfirm()`:
  ```ts
  function handleConfirmClick() {
    if (단가미등록행.length > 0) { set단가미등록확인대기(true); return; }
    if (미분류행.length > 0) { set미분류확인대기(true); return; }
    applyConfirm();
  }
  ```
- 신규 `ConfirmDialog`(기존 미분류 다이얼로그와 동일한 `danger` 스타일) — "그래도 확정" 클릭 시
  바로 `applyConfirm()`이 아니라 **미분류 체크로 이어감**(둘 다 있으면 순서대로 확인):
  ```ts
  onConfirm={() => {
    set단가미등록확인대기(false);
    if (미분류행.length > 0) { set미분류확인대기(true); return; }
    applyConfirm();
  }}
  ```
- 안내 문구: "OO건(단가 미등록으로 청구서에서 빠진 품목)이 있습니다. 단가마스터에 단가를 등록한 뒤
  다시 시도하거나, 그래도 진행할 수 있습니다." + 품목별 목록(품목명·수량)
- 추가로, 미리보기 단계에서도 눈에 띄도록 상단에 빨간색 배너(수량불일치와 같은 자리, 더 심각한
  문제라 색상 구분)도 함께 넣음 — 계획에는 없었지만 미분류와 달리 원본 표에 체크 표시로도 안 보이는
  문제라 확정 클릭 전에도 알 수 있게 하는 게 낫다고 판단(승인된 확정 차단 경고와 별개로 추가한
  보조 장치, 제거하기 쉬운 단순 조건부 렌더링)
